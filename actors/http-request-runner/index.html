HTTP Request — Bulk API Calls for Clay, n8n & Make

Send HTTP requests to any API (GET, POST, PUT, PATCH, DELETE) from Clay, n8n, Make, Zapier or the Apify API: one call or thousands in a batch, with {{variable}} templating, retries, redirects, JSON field extraction and webhook callbacks. A Clay HTTP API alternative at $2 per 1,000 requests.

Run on Apify →See pricing

What it does

Call any REST API or webhook from Clay, n8n, Make, Zapier or your own code, with no HTTP plan upgrade and no server to run. Send one request or a batch of thousands (GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS) with custom headers, query parameters and JSON, form or raw bodies. Get back one clean row per request: status code, response headers, the body (parsed JSON, text, or base64 for binary), extracted fields pulled out of the JSON by path (e.g. data.items[0].email), duration, attempts and the full redirect chain. It works as a Clay HTTP API alternative: Clay only offers its HTTP API integration on higher plans, but any Clay table can run an Apify actor per row. It also does bulk API requests for n8n and Make (one run, many calls, results as items), and you can forward every response to a webhook (a Clay table webhook, n8n or Make) with an optional lookupKey to match rows.

Batch and templating. Put {{field}} placeholders in the URL, headers, query or body and pass a variables list: one request per row, e.g. enrich 5,000 domains with one input. URL values are percent-encoded, JSON bodies are escaped, and a lone "{{count}}" keeps its number type. Reliable by default: retries with exponential backoff on network errors, timeouts, 429 and 5xx (honours Retry-After; POST is never blindly re-sent after a 500), per-host concurrency limits for rate-limited APIs, redirects (credentials are dropped on cross-domain hops), gzip/brotli decoding, and a size cap on bodies.

Limits and honest notes

  • You pay only for requests that got a response from the server, whatever the status code (a 404 or 500 is still a response). Network failures, timeouts, invalid URLs, template errors and blocked targets are free.
  • Fast to start: a synchronous single-request call (run-sync-get-dataset-items) typically returns within a few seconds end to end, including the actor start, at 256 MB memory. Batches run up to 20 requests in parallel.
  • Up to 25,000 requests per run (requests × variables rows), 20 in flight at once. Synchronous API calls (run-sync) wait at most 300 seconds, so keep sync batches to a few hundred quick requests or use the dataset/callback for more.
  • Response bodies are capped at 2 MB by default and 9 MB at most (the Apify dataset item limit). Larger bodies are cut off and flagged with bodyTruncated. Truncated JSON is returned as text. The data field (riceman-compatible copy of body) is filled for bodies up to 1 MB.
  • Only public http and https targets. Localhost, private networks (10.x, 172.16-31.x, 192.168.x), link-local and cloud-metadata addresses (169.254.169.254) and .internal/.local hostnames are blocked, and the check is repeated on every redirect and at connect time, so DNS rebinding is blocked too. Host header overrides are rejected, and URLs with user:password@ are refused (send credentials as a header).
  • POST and PATCH are retried only when the server certainly did not process the request (429, 503 or connection refused), to avoid duplicate side effects. GET, PUT, DELETE, HEAD and OPTIONS are also retried on 500, 502 and 504. Retry-After waits are capped at 20 seconds.
  • Requests go out from Apify's shared datacenter IPs without a proxy. Sites that block datacenter traffic or need a browser (JavaScript, CAPTCHAs) are out of scope; this is a tool for APIs and webhooks.
  • Respects your run budget: set a maximum total charge and the run stops cleanly at the cap, with every delivered row charged exactly once.

Use it from code

Run the actor through the Apify API with the input above.

cURL

curl -X POST "https://api.apify.com/v2/acts/actor-forge~http-request-runner/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://jsonplaceholder.typicode.com/users/1", "method": "GET", "extract": ["email", "company.name", "address.city"]}'

JavaScript (Node.js)

// Node.js 18+ (built-in fetch). Set APIFY_TOKEN in your environment.
const input = {
  "url": "https://jsonplaceholder.typicode.com/users/1",
  "method": "GET",
  "extract": [
    "email",
    "company.name",
    "address.city"
  ]
};

const res = await fetch(
  "https://api.apify.com/v2/acts/actor-forge~http-request-runner/run-sync-get-dataset-items",
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.APIFY_TOKEN}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(input),
  }
);
const items = await res.json();
console.log(items.length, items[0]);

Python

# pip install apify-client   (set APIFY_TOKEN in your environment)
import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run_input = {
    "url": "https://jsonplaceholder.typicode.com/users/1",
    "method": "GET",
    "extract": [
        "email",
        "company.name",
        "address.city"
    ]
}

run = client.actor("actor-forge/http-request-runner").call(run_input=run_input)
for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item)

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.
