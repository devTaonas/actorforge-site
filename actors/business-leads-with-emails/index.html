Google Maps Email Extractor Alternative — Business Leads

What it does

A Google Maps email extractor alternative that never scrapes Google. Type a city and a business type ("dentists in Austin TX", "restaurants in Berlin") and get one lead row per business: name, category, address, phone, website and company emails, plus company socials, the contact page, a contact-form flag and website signals for agency prospecting (HTTPS, CMS or site builder, shop platform, analytics and ad pixels, booking widget, mobile viewport, copyright year). Places come from the open Overture Maps Foundation places dataset (80M+ businesses worldwide, refreshed monthly). Then each business's own website is read once (home page plus up to 2 contact / imprint pages, robots.txt obeyed, honest user agent, no proxies) to add the emails and phones it publishes. Every email carries its source (Overture or the exact website page it was found on). Only company mailboxes are kept: personal-looking addresses are dropped and counted. $1 per 1,000 places + $1.50 per 1,000 websites read (chains sharing a website are charged once; blocked or failed sites are free): about $2.50 per 1,000 fully enriched leads, a third of the leading Google Maps email scrapers.

What it is not: this is not Google data. There are no Google reviews, star ratings, review counts, opening hours or photos. Places are as fresh as the latest monthly Overture release, coverage varies by country, and some websites block automated readers (those rows still come back, free of the website charge).

Limits and honest notes

  • Open data plus the businesses' own websites, not Google: no reviews, ratings, review counts, opening hours, photos, popular times or price levels. The Google Maps link in each row is a plain search URL built from the name and address; nothing is fetched from Google.
  • Websites are read politely: robots.txt is obeyed (a robots.txt error counts as "disallow"), one request per site at a time, up to 3 pages per site, about 20 seconds per site, and the actor stops at the first 403, 429 or CAPTCHA. It never uses proxies or a browser, so sites behind strict bot protection (often 20-35% of a city's sites) come back as websiteStatus blocked with the Overture contacts only, and are not charged.
  • websiteStatus tells you what happened for each row: ok (read, contacts found), no-contacts (read, nothing found, free), blocked, robots-disallowed, unreachable, skipped-budget (all free), no-website, social-only (the only "website" is a Facebook, Instagram, linktree, WhatsApp or directory page; never fetched) or not-requested.
  • Email coverage depends on the city and trade. Measured on 2026-10-22 (50 places each): Austin dentists 68% with a company email from Overture alone, 74% after reading the websites; Berlin restaurants 0% from Overture alone (the top-confidence rows carry no email), 52% after. Every row had a phone. Emails shown only as images or behind JavaScript forms are not found.
  • Company contacts only, by allowlist. Kept: role and department mailboxes from a multilingual dictionary (info@, kontakt@, office@, praxis@, termine@, bookings@), mailboxes made of the business name or domain, and free-mail addresses containing the business name. Every other address on the business's domain is dropped and counted in droppedPersonalEmails: surnames (mueller@), first names, jsmith@, first.last, initials and Impressum owner addresses. A chain's location mailboxes are kept only on the row whose name matches. Social links are company profiles only (never linkedin.com/in/). You remain responsible for how you use the data under GDPR, CAN-SPAM and similar laws.
  • Chains: Overture often links a chain's locations to a store-locator page on one corporate domain. That domain is read once per run and charged once; every location gets the same corporate contacts.
  • Website signals come from the home page HTML only (no JavaScript is run): a CMS that hides its fingerprints, or a copyright year printed by a script, is reported as null. technologies lists at most 20 detections from a curated set of site builders, shops, analytics, ad pixels and booking widgets.
  • One area per run, up to 1.5 x 1.5 degrees (about one metro area). Up to 5,000 places per run; 200 places usually take 1-3 minutes. The spend limit is respected: place rows are reserved first, websites are read only while the budget lasts (the rest come back skipped-budget, free).

Use it from code

Run the actor through the Apify API with the input above.

cURL

curl -X POST "https://api.apify.com/v2/acts/actor-forge~business-leads-with-emails/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \

JavaScript (Node.js)

// Node.js 18+ (built-in fetch). Set APIFY_TOKEN in your environment.
const input = {
  "location": "Austin, TX",
  "categories": [
    "dentist"
  ],
  "maxPlaces": 10
};

const res = await fetch(
  "https://api.apify.com/v2/acts/actor-forge~business-leads-with-emails/run-sync-get-dataset-items",
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.APIFY_TOKEN}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(input),
  }
);
const items = await res.json();
console.log(items.length, items[0]);

Python

# pip install apify-client   (set APIFY_TOKEN in your environment)
import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run_input = {
    "location": "Austin, TX",
    "categories": [
        "dentist"
    ],
    "maxPlaces": 10
}

run = client.actor("actor-forge/business-leads-with-emails").call(run_input=run_input)
for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item)

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.
