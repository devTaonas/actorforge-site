Google Trends Scraper & API Alternative — Trending Searches by Country

What it does

Google Trends has no official public API, and the website is built for clicking, not for feeding a newsroom alert, a content calendar or an ad team every hour. This actor reads Google's official Trending Now RSS feed for any of the 125 countries the feed accepts and turns it into one row per trend: country, rank, keyword, approximate search traffic parsed to a number (2K+ becomes 2000, with the original text kept), the time the trend started, a picture and the news articles behind it.

Switch on onlyNewSinceLastRun and schedule it, and each run returns only the trends it has not delivered before for that country, keyword and start day. Skipped trends are not charged, so an hourly monitor costs only what is genuinely new.

There is a second, best-effort part for keyword research: up to 20 keywords with interest over time, interest by region and top + rising related queries, for any timeframe, location, category and search type (web, news, YouTube, images or Google Shopping). Google rate-limits those endpoints, so when it answers with a 429, 403 or CAPTCHA the actor stops that part, keeps what it already has and charges nothing for unfinished keywords.

How it works

  1. For each country in geos, the actor requests Google's official Trending Now RSS feed (one request per country, paced at about one per second).
  2. Each trend becomes a row with its rank, keyword, traffic bucket parsed to a number, start time, picture and news articles (title, URL, publisher, picture).
  3. With onlyNewSinceLastRun, trends already returned under the same monitorName are skipped and not charged; the memory lives in the key-value store trends-seen-<name>.
  4. If you add keywords, it calls the same JSON endpoints the Trends website uses, one request every 3 seconds, and returns timeline, region and related-query rows.
  5. On any rate limit or CAPTCHA it stops the explore part for the rest of the run, never retries blocks, uses no proxies, and respects robots.txt and your run budget.

Limits and honest notes

  • Trending Now comes from Google's official RSS feed, which currently lists about 10 trends per country (fewer for small countries) — the newest ones, not the full Trending Now page with 24/48-hour filters. Traffic is Google's bucketed estimate (200+, 2K+, 1M+), not an exact count.
  • The 125 countries in the input list are every ISO country code the feed accepted on 2026-10-20; Google answers unknown codes with an error.
  • Interest over time / by region / related queries is best-effort. It uses the same JSON endpoints as trends.google.com and Google rate-limits them, especially from shared cloud IPs. On a 429, 401/403, CAPTCHA or 'unusual traffic' page the actor stops that part for the rest of the run (blocks are never retried and no proxies are used; only network errors and Google 5xx errors are retried once), delivers what it already has and charges nothing for unfinished keywords. Run small keyword lists and try again later if you are blocked.
  • Requests are sequential and paced (one every 3 seconds for explore, one per second for the feed), so 20 keywords take about 1-2 minutes.
  • Values are Google's relative scores (0-100 within a comparison, region values 0-100 per keyword), not search volumes. Related 'rising' values are growth percentages; 'Breakout' means more than +5000%. Regions without enough data are left out.
  • robots.txt on trends.google.com is re-read every run and respected: the /explore? web pages are never requested (trendsUrl in the output is only a link for you to open).
  • The run's spend limit is respected: rows are charged before they are delivered and the run stops when the limit is reached.

FAQ

Is there an official Google Trends API for trending searches?

Google publishes Trending Now as an RSS feed per country, which this actor reads and normalizes. The interest-over-time, region and related-query data uses the same JSON endpoints the Trends website calls, which are rate-limited, so that part is best-effort.

How many trending searches per country does it return?

The official feed currently lists up to about 10 of the newest trends per country, fewer for small countries. You can cap it lower with maxItemsPerGeo. It is not the full Trending Now page with its 24 and 48-hour filters.

Is the traffic number an exact search count?

No. Traffic is Google's bucketed estimate such as 200+, 2K+ or 1M+. The actor parses it to a number (2K+ becomes 2000) so you can sort and filter, and keeps the original text in approxTrafficText.

What happens if Google blocks the keyword explore part?

On a 429, 401/403, CAPTCHA or unusual-traffic page the actor stops the explore part for the rest of the run, delivers what it has and charges nothing for keywords it could not finish. Trending Now from the RSS feed is unaffected. Run smaller keyword lists and try again later.

How do I only get new trends on an hourly schedule?

Set onlyNewSinceLastRun to true and give each schedule its own monitorName. Trends already returned for the same country, keyword and start day are skipped and not charged.

Are the interest values search volumes?

No. They are Google's relative scores from 0 to 100 within each comparison (up to 5 keywords at once), and region values are 0-100 per keyword. Rising related queries show growth percentages, and Breakout means more than +5000%.
