What it does

Remote jobs from four job boards in one clean, deduplicated feed. This remote jobs scraper / remote job API reads Remote OK, We Work Remotely (WeWorkRemotely, all category feeds), Jobicy and Arbeitnow (remote roles only) through their public APIs and RSS feeds, and returns every work-from-home job in one schema: title, company, logo, where you can work from ("Anywhere in the World", "USA Only", "🇩🇪 Germany, 🇫🇷 France" and "Remote (US)" all normalized to a locationRestrictions list like ["Worldwide"] or ["USA"]), job type, category, tags, salary min/max/currency/period (structured where the board has it, parsed from the pay range otherwise), posted date, apply URL and the full description as plain text and Markdown. The same job posted on several boards comes back once, with every board listed in sources. Filter by keywords, excluded words, category, country or region ("Europe" matches jobs open to Germany, and vice versa), job type, minimum salary and posted within N days. Use it for job alerts and newsletters, a remote job board or Slack channel feed, recruiting and sourcing, labour-market and salary research, or as a job board scraper for AI agents. $0.80 per 1,000 jobs, about 19× cheaper than the top-ranked remote jobs scraper ($15 per 1,000) and below every other remote-jobs actor we found. Duplicates, filtered-out jobs and boards that fail are never charged.

Limits and honest notes

  • Sources: Remote OK, We Work Remotely, Jobicy and Arbeitnow. Himalayas and Remotive are not included: their API terms don't allow redistributing or reselling their jobs.
  • Each board's feed holds its recent jobs only: Remote OK about the newest 100, We Work Remotely about 30 days across its category feeds, Jobicy pages back up to 3,000 jobs and Arbeitnow up to 3,000 listings per run (about 1 in 10 Arbeitnow listings is remote). Older listings can't be recovered.
  • Arbeitnow is a European (mostly German) board; only jobs it flags as remote are returned, and many are remote within one country.
  • Location restrictions are normalized from each board's wording. Unknown places (usually cities) are kept as written; a job that states no restriction has remoteType 'unspecified'.
  • Salary appears only where the board or the posting publishes it. Structured board salaries are passed through; otherwise a pay range is parsed conservatively. The minimum-salary filter compares yearly amounts in the job's own currency (no exchange-rate conversion).
  • Dedupe matches normalized company + title with compatible locations, so reworded copies of the same job ("Sr." vs "Senior", "(m/w/d)", "- Remote") merge, while the same title in different countries stays separate.
  • When more jobs match than Maximum jobs, they're picked evenly across boards (newest first within each), so one busy board doesn't fill the run.
  • Email addresses and phone numbers are removed from descriptions. Every row keeps the job's URL on the source board and an attribution line; please link back to the source board when you display the jobs, as each board's API terms ask.
  • Respects your run budget: set a maximum total charge and the run stops cleanly at the cap, with no job charged twice.

JavaScript (Node.js)

// Node.js 18+ (built-in fetch). Set APIFY_TOKEN in your environment.
const input = {
  "keywords": [
    "developer"
  ]
};

const res = await fetch(
  "https://api.apify.com/v2/acts/actor-forge~remote-jobs/run-sync-get-dataset-items",
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.APIFY_TOKEN}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(input),
  }
);
const items = await res.json();
console.log(items.length, items[0]);

Python

# pip install apify-client   (set APIFY_TOKEN in your environment)
import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run_input = {
    "keywords": [
        "developer"
    ]
}

run = client.actor("actor-forge/remote-jobs").call(run_input=run_input)
for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item)

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.
