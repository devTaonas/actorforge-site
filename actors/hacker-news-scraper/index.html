Hacker News Scraper — Stories & Comments by Keyword

Search Hacker News stories and comments by keyword: Show HN, Ask HN, polls and job posts too, with points, comment count, author, link and date. Filter by minimum points and time window, newest first or by relevance. No login. $0.10 per 1,000 items.

Run on Apify →See pricing

What it does

Search Hacker News by keyword and get clean rows of stories and comments, with points, comment count, author, link and date, from the public Algolia HN Search API that Hacker News itself links to. No login, no API key, no browser.

- Item types: stories, comments, Show HN, Ask HN, polls and job posts, alone or combined. - Minimum points to keep only stories that took off, and a time window from one hour to a year. - Newest first for monitoring, or most relevant for research ("what did HN say about X?"). - Comments carry the title of the story they were posted on; stories carry their outbound link and a Show HN / Ask HN label.

Limits and honest notes

  • Hacker News only, through the public Algolia HN Search API (hn.algolia.com), paced at 2 requests per second. For the same search across Bluesky, Lemmy, Mastodon, GitHub and DEV, use Brand Mentions Monitor.
  • Search is Algolia full-text search with its own typo tolerance, so a short query can also match similar words. Use "Exclude keywords" or a longer phrase to narrow it.
  • Comment and story text is plain text, cut at 1,000 characters (textTruncated says when). Points are public for stories only.
  • Public data only: author handles as shown on Hacker News, no e-mail addresses or profiles. Items deleted on HN disappear from the index.
  • Respects your run budget: set a maximum total charge and the run stops cleanly at the cap. No matches, bad input or an API outage give a free status row.

Use it from code

Run the actor through the Apify API with the input above.

cURL

curl -X POST "https://api.apify.com/v2/acts/actor-forge~hacker-news-scraper/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"keywords": ["apify"], "sinceHours": 720, "maxPosts": 20}'

JavaScript (Node.js)

// Node.js 18+ (built-in fetch). Set APIFY_TOKEN in your environment.
const input = {
  "keywords": [
    "apify"
  ],
  "sinceHours": 720,
  "maxPosts": 20
};

const res = await fetch(
  "https://api.apify.com/v2/acts/actor-forge~hacker-news-scraper/run-sync-get-dataset-items",
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.APIFY_TOKEN}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(input),
  }
);
const items = await res.json();
console.log(items.length, items[0]);

Python

# pip install apify-client   (set APIFY_TOKEN in your environment)
import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run_input = {
    "keywords": [
        "apify"
    ],
    "sinceHours": 720,
    "maxPosts": 20
}

run = client.actor("actor-forge/hacker-news-scraper").call(run_input=run_input)
for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item)

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.
