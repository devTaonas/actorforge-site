Academic Paper Search — OpenAlex, arXiv, PubMed & Crossref

Search 250M+ scholarly papers across OpenAlex, arXiv, PubMed and Crossref, or look up DOIs, arXiv ids and PMIDs. One clean row per paper: title, abstract, authors with ORCID, year, venue, citations, open-access PDF link. $1 per 1,000 papers.

What it does

Academic paper search across four open scholarly databases, in one consistent format. Search OpenAlex (250M+ works with citation counts, abstracts and open-access links), arXiv (preprints), PubMed (biomedical literature) and Crossref (publisher metadata for 160M+ DOIs), or paste a list of DOIs, arXiv ids, PMIDs, PMC ids or OpenAlex ids to look them up. Every paper comes back in the same shape whatever the source: title, abstract as plain text, authors with ORCID iDs, year and publication date, journal or venue, publisher, type, cited-by count, reference count, open-access status, licence and PDF link, topics, and every id we know (DOI, arXiv id, PMID, PMCID, OpenAlex id). Filter by year range, open access, publication type, minimum citations, author and journal, and sort by relevance, newest or most cited. Searching several sources at once? The same paper found twice (same DOI) is returned once and charged once. It works as a research papers API and a Google Scholar alternative built on open data, with no captchas, no blocked IPs and no scraping: for literature reviews, systematic-review screening, citation analysis, research dashboards, RAG pipelines, and AI agents that need real references (call it as a tool through Apify's MCP server). $1 per 1,000 papers, with no per-run fee and no compute bill on top. Ids not found and sources that fail are never charged.

Data sources and attribution. OpenAlex data is CC0. Crossref metadata is open (facts are not copyrightable; abstracts remain the publishers'). PubMed data comes from the NLM via NCBI E-utilities: NLM does not endorse this tool, and abstracts may be copyrighted by their publishers. Thank you to arXiv for use of its open access interoperability. We follow each API's usage policy: requests are rate-limited per source (arXiv at most one request every 3 seconds, PubMed at most 3 a second, Crossref's public pool limits) and identify this actor in the User-Agent.

Limits and honest notes

  • Up to 10,000 papers per source per run (OpenAlex and PubMed paging limits). Split bigger pulls by year range.
  • OpenAlex without an API key shares a small daily budget per network (roughly 100 searches a day, reset at midnight UTC). When it runs out, the search continues on Crossref and the run summary says so. Add your free OpenAlex key for your own, 10x larger budget. Id lookups are much cheaper and rarely affected.
  • arXiv and PubMed have no citation counts: sorting by citations falls back to relevance there, and a minimum-citations filter skips them. arXiv has preprints only, so other publication types skip it.
  • Crossref ranks loosely (it matches any query word), so records that don't contain most of your query words are dropped before delivery and never charged. For the same reason, a Crossref keyword search is always in relevance order (sorting is applied when you list by author or venue without a query). Crossref has no open-access flag: open access there means a Creative Commons licence.
  • Abstracts are only as complete as the sources: some publishers don't share them (common for Elsevier in OpenAlex and Crossref). The abstract field is then empty.
  • arXiv is queried at most once every 3 seconds, as its terms require, so a large arXiv pull is slower (about 100 papers per 3 seconds).
  • Authors are listed up to 50 per paper (authorCount gives the full number), with ORCID iDs where the source has them. No email addresses or affiliations are output.
  • Respects your run budget: set a maximum total charge and the run stops cleanly at the cap, with no paper charged twice.

Use it from code

Run the actor through the Apify API with the input above.

cURL

curl -X POST "https://api.apify.com/v2/acts/actor-forge~academic-research/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"query": "large language models for medical diagnosis"}'

JavaScript (Node.js)

// Node.js 18+ (built-in fetch). Set APIFY_TOKEN in your environment.
const input = {
  "query": "large language models for medical diagnosis"
};

const res = await fetch(
  "https://api.apify.com/v2/acts/actor-forge~academic-research/run-sync-get-dataset-items",
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.APIFY_TOKEN}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(input),
  }
);
const items = await res.json();
console.log(items.length, items[0]);

Python

# pip install apify-client   (set APIFY_TOKEN in your environment)
import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run_input = {
    "query": "large language models for medical diagnosis"
}

run = client.actor("actor-forge/academic-research").call(run_input=run_input)
for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item)

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.
