PDF OCR API: Turn Scanned PDFs into Searchable Text

Send links to scanned or mixed PDFs and get clean text back page by page, with a confidence score for every page that needed OCR.

What it does

A scanned PDF is just a stack of pictures. Search boxes, LLMs and full-text indexes see nothing inside it until each page has been run through OCR. The PDF OCR actor does that for you in the cloud: paste links to archive scans, faxes, signed contracts, invoices or photocopied letters, and it returns the text of each page with line and paragraph breaks kept.

Many real PDFs are mixed: a digital report with a few scanned appendix pages, or a contract where only the signature pages were scanned. In the default auto mode the actor reads pages that already have a text layer directly (exact, and charged at $0.30 per 1,000 pages) and only OCRs the pages that are images (charged at $3 per 1,000 pages). You do not pay OCR prices for text that was already there.

Recognition runs on Tesseract 5 with its LSTM models in 29 languages, up to 4 per run. Every OCR'd page carries a confidence score, so you can spot the pages worth a human look, and optional word-level bounding boxes help with redaction and highlighting. It suits records teams digitising archives, developers adding a PDF OCR step to an app, and anyone feeding paper documents into a RAG pipeline.

How it works

  1. You pass one or more PDF links in urls (images such as PNG, JPEG and TIFF are accepted too).
  2. Each PDF is opened page by page; in auto mode, pages with an existing text layer are read directly and the rest are rendered at the chosen dpi (300 by default).
  3. Rendered pages are recognised by Tesseract 5 in the languages you selected, with an optional page segmentation mode for forms or receipts.
  4. Results are written as one row per page (the default for this actor) or one row per PDF, with text, word count, OCR confidence and page counts by method.
  5. Failed downloads, unreadable files and blank pages are reported but not charged, and the run stops cleanly at your maximum total charge.

Use cases

Make a scanned archive searchable

Run a folder of digitised letters, minutes or old reports through the actor and index the returned text in your search engine. The per-page rows map cleanly onto page-level search hits, so users land on the right page of the original scan.

Review signed contracts and invoices

Signed agreements and supplier invoices often come back as scans. OCR them to text so you can search for clauses, amounts and party names, and use the confidence score to route weak pages to manual review.

Process mixed digital and scanned PDFs

When a batch contains both born-digital PDFs and scans, auto mode reads the digital pages exactly at the text-layer price and only OCRs the image pages. Use ocr-all only when a PDF's hidden text layer is known to be poor.

Feed paper documents to an LLM

Turn scanned reports into plain text that a RAG pipeline or AI agent can chunk and embed. If you need Markdown with headings for digital PDFs as well, see Any URL to Markdown.

Limits and honest notes

  • Tesseract reads printed and typed text very well (95%+ confidence on clean scans); handwriting, low-resolution photos, heavy stamps and decorative fonts come out poorly. The confidence score tells you which pages to check.
  • Output is plain text in reading order with line and paragraph breaks. Tables come out as lines of text, not structured tables. Images and charts have no text to extract.
  • Pages rotated by 90° or 180° are not auto-rotated; slightly skewed scans are fine.
  • Up to 4 languages per run; picking only the languages your documents use is faster and more accurate. Modern Greek is not available.
  • HEIC/AVIF photos and SVG are not supported (convert photos to JPEG). Files up to 100 MB; PDFs up to 2,000 pages each (200 by default).
  • Password-protected PDFs need the password input. Links that return a web page instead of a file are reported and not charged.
  • Respects your run budget: set a maximum total charge and processing stops cleanly at the cap, with no page charged twice.

FAQ

How do I make a scanned PDF searchable with an API?

Send the PDF's URL in urls and the actor returns the recognised text for each page. Store that text in your search index alongside the original file. The actor returns text, not a new PDF with an embedded text layer.

Will I pay OCR prices for pages that already contain text?

No, not in the default auto mode. Pages with a text layer are read directly and charged at $0.0003 per page; only image pages are OCR'd at $0.003 per page. Switch pdfMode to ocr-all only if a PDF's existing text layer is broken.

Can it OCR password-protected PDFs?

Yes, if you are entitled to open them. Put the password in the password field; it is used for every PDF in that run, so group files that share a password into one run.

What happens with sideways or upside-down scans?

Pages rotated by 90 or 180 degrees are not auto-rotated, so rotate them before submitting. Slightly skewed scans are handled fine.

How long can a PDF be?

Files up to 100 MB and up to 2,000 pages per PDF are supported. By default only the first 200 pages of each PDF are processed; raise maxPagesPerPdf for longer documents. Longer PDFs are marked as truncated.

# pip install apify-client   (set APIFY_TOKEN in your environment)
import os

client = ApifyClient(os.environ["APIFY_TOKEN"])

run = client.actor("actor-forge/pdf-ocr").call(run_input=run_input)
for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item)

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.
