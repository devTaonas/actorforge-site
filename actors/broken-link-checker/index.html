Broken Link Checker — Find 404s, Redirects & Dead Links

Crawl your website and find every broken link: 404s, 5xx errors, dead domains, timeouts, SSL errors, redirect chains, broken images and missing #anchors. One row per broken URL with the pages it is on and the anchor text. $0.50 per 1,000 pages + $0.20 per 1,000 links.

What it does

Find every broken link on your website before your visitors (and Google) do. Give it your site's URL and it crawls your pages (following links and the sitemap, respecting robots.txt) and checks every link, image and, optionally, script, stylesheet and iframe on them, including links to other websites. You get one row per broken URL with the pages it appears on (up to 50 listed, with the anchor text) and the total page count, so a dead link in a site-wide footer is one row "found on 480 pages", not 480 rows. Each row has the HTTP status (404, 410, 500…), the error type (HTTP error, dead domain/DNS, timeout, SSL certificate, connection refused, redirect loop, malformed URL), the full redirect chain and final URL. Optional modes add redirects (so you can update links that bounce through 301s) or every link checked, and missing #anchors (links to headings that no longer exist). Links behind bot protection (LinkedIn's 999, Cloudflare challenges, 403/429 from other sites) are reported as blocked, not broken, so your report has no false alarms. Use it for SEO audits, website migrations, documentation QA, content maintenance, agency client reports and scheduled monitoring. $0.50 per 1,000 pages crawled + $0.20 per 1,000 unique links checked: a 100-page site with 300 unique links (the 100 pages included) costs about $0.11, with no compute bill on top.

Limits and honest notes

  • Pages are fetched as static HTML without a browser: fast and cheap, and it covers almost all websites. Links that exist only after JavaScript runs (single-page apps that render their menus client-side) are not found.
  • Some sites refuse automated requests: LinkedIn answers 999, others answer 403 or 429 or show a Cloudflare challenge. Those links usually work in a browser, so they are reported as 'blocked' (status kept) instead of broken. Hide them with 'Report bot-blocked links' or skip them with 'Ignore links matching'.
  • Each unique link is checked once with a HEAD request; when a server refuses HEAD or answers a common error status (400, 403, 404, 405, 410, 5xx…) or drops the connection, the result is confirmed with GET before it is called broken. Redirects are followed up to 10 hops, with the full chain recorded. Each request times out after 20 seconds.
  • Polite by design: at most 2 requests at a time per host, and a 429 'Too Many Requests' pauses that host for its Retry-After. Very link-heavy external hosts (GitHub, for example) therefore take a while to check.
  • Crawling respects robots.txt and stays on your site and under the start URL's path, unless you set include globs. Links to pages robots.txt disallows are still checked with a single request, since checking a link is not crawling. If a site's robots.txt can't be fetched (HTTP 5xx or a network error, after one retry), none of that site's pages are crawled (RFC 9309) and its start URL is reported as skipped, not charged. Login-protected pages are not supported.
  • Missing-anchor checks compare #fragments with the ids in the static HTML of crawled pages; anchors added by JavaScript are reported as missing. Results are delivered when the crawl finishes; runs resume after a platform migration without re-charging work already done.
  • Links to internal network addresses (localhost, private IPs, cloud metadata) are never requested and never charged.
  • Respects your run budget: set a maximum total charge and the run stops cleanly at the cap and reports everything checked so far.

Use it from code

Run the actor through the Apify API with the input above.

cURL

curl -X POST "https://api.apify.com/v2/acts/actor-forge~broken-link-checker/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"startUrls": ["https://crawlee.dev/js/docs/quick-start"]}'

JavaScript (Node.js)

// Node.js 18+ (built-in fetch). Set APIFY_TOKEN in your environment.
const input = {
  "startUrls": [
    "https://crawlee.dev/js/docs/quick-start"
  ]
};

const res = await fetch(
  "https://api.apify.com/v2/acts/actor-forge~broken-link-checker/run-sync-get-dataset-items",
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.APIFY_TOKEN}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(input),
  }
);
const items = await res.json();
console.log(items.length, items[0]);

Python

# pip install apify-client   (set APIFY_TOKEN in your environment)
import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run_input = {
    "startUrls": [
        "https://crawlee.dev/js/docs/quick-start"
    ]
}

run = client.actor("actor-forge/broken-link-checker").call(run_input=run_input)
for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item)

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.
