Wayback Machine Scraper: Archive.org Snapshots and URL History

List every archived capture of a page or site from the Internet Archive, filtered down to the versions that actually changed.

Run on Apify →See pricing

What it does

The Wayback Machine holds years of captures for most public websites, but browsing its calendar one day at a time is slow, and the raw CDX index is awkward to query. This actor turns the official Wayback CDX API into clean dataset rows: capture time, original URL, HTTP status, MIME type, size, content digest and archive links with and without the Wayback toolbar.

You can look up a single page, a folder (example.com/blog/*), a host or a whole domain with subdomains. By default it keeps only unique content versions and flags each with changedFromPrevious, so a page captured thousands of times collapses to the moments it really changed. Alternatively keep one capture per hour, day, month or year, or one row per distinct URL to list every page ever archived on a site.

Summary mode returns one row per site with first and last capture, totals, captures per year, missing years and longest gap. You can also fetch the archived HTML of captures as Markdown or text. Snapshots cost $2 per 1,000 rows, summaries $0.004 per exact URL or $0.01 per prefix, host or domain, and archived content $0.004 per page. The data comes from the Internet Archive; ActorForge is not affiliated with it.

How it works

  1. You list pages, folders or domains in urls and choose a matchType: exact, prefix, host or domain.
  2. The actor queries archive.org's CDX index, applying your from/to dates, statusFilter, mimeFilter and collapse mode.
  3. Requests are paced (about one per second, two URLs in parallel) and retried with back-off on rate limits, server errors and timeouts.
  4. Rows are written per capture (snapshots mode) or per input (summary mode), capped by maxSnapshotsPerUrl.
  5. With fetchContent on, the first maxContentPages HTML captures with status 200 are downloaded and their title and main content added as Markdown or text.

Limits and honest notes

  • Data comes from the Internet Archive's public Wayback CDX API. Captures the archive doesn't have (never crawled, excluded by the site owner, or very recent) can't be returned; such inputs get a free row saying so.
  • archive.org is a non-profit and sometimes slow: exact-URL lookups take about a second, but prefix/host/domain lookups take 20–40 s per index page (each page covers several thousand captures). The actor paces its requests (about one per second, two URLs in parallel) and retries rate limits (HTTP 429), server errors and timeouts with backoff; a URL that still fails gets a free error row.
  • Prefix/host/domain results come in URL order (then time), not purely by date. Newest-first is available for exact URLs only. These queries stop after 10 index pages per input by default (raise Max index pages to go deeper). On multi-URL results, collapsing works per URL: "one per day" keeps one capture per day for each URL.
  • Unique-versions mode compares each capture with the previous one (archive.org's digest collapse), so a page that changes back to an earlier version shows up again — that is a real change.
  • Summary counts for exact URLs come from the Wayback Machine's capture calendar (all captures, monthly precision for date ranges). With status/MIME filters, or for prefix/host/domain, they are counted from the index (up to 100,000 captures or the index page cap; scanComplete says whether the count is complete).
  • Archived page content is extracted from the raw capture as archived; pages that were built by JavaScript may come out nearly empty, and images/CSS are not downloaded. Content is fetched only for HTML captures with HTTP 200 and is capped at 200,000 characters.
  • Respects your run budget: set a maximum total charge and the run stops cleanly at the cap, with no row charged twice.

FAQ

How do I get all Wayback Machine snapshots of a URL?

Put the URL in urls with matchType exact and set collapse to none to get every capture, or leave the default digest to keep only captures where the content changed. Raise maxSnapshotsPerUrl (1,000 by default) for heavily archived pages.

How do I list every archived page of a domain?

Use matchType domain (or the *.example.com shortcut) with collapse set to unique-urls. Domain lookups are slow on archive.org's side, about 20-40 seconds per index page, and stop after maxIndexPagesPerUrl pages (10 by default).

Can I get the newest captures first?

Yes, for exact URLs only: set newestFirst to true. Prefix, host and domain results come in URL order, then time.

Why does a page show up as changed back to an old version?

Unique-versions mode compares each capture with the previous one, so a page that reverts to earlier content is flagged again. That is a real change in the archive.

What if a URL has never been archived?

Captures the archive does not have, because the page was never crawled, was excluded by its owner or is very recent, cannot be returned. Such inputs get a free row saying so.
