Bluesky Posts Search - Keyword & Hashtag Posts, No Login

Search Bluesky posts by keyword, phrase or hashtag without an account or API key: text, link, author handle, time, likes, replies, reposts, language and linked URL. Filter by language, author and time window; monitor mode returns only new posts. $0.30 per 1,000 posts.

What it does

Search Bluesky posts by keyword, phrase or hashtag, with no Bluesky account, app password or API key. Give it one or more search queries (a brand, a product, a topic, a #hashtag) and it returns matching public Bluesky posts, newest first or Bluesky's top-ranked: post link, post text (up to 1,000 characters), the public author handle, time posted, likes, replies and reposts (including quotes), the post's language and any linked URL. Filter by language, author handle and time window (last hour to last year), exclude noise words, or drop replies. Switch on monitor mode for scheduled runs and each run returns only posts you have not seen yet: a cheap Bluesky monitoring and social listening feed for brand tracking, PR, community and devrel teams, research datasets, Slack alerts via Make, n8n or Zapier, and AI agents. It uses Bluesky's public AppView search API (api.bsky.app), whose robots.txt explicitly allows crawling the public API. Only public posts and public handles are returned: no follower lists, profiles or emails, and accounts that opted out of logged-out visibility are skipped. $0.30 per 1,000 posts, with no start fee and no compute bill on top. Need Hacker News, GitHub, Lemmy and Mastodon too? See Brand Mentions Monitor below.

Limits and honest notes

  • Data: Bluesky's public AppView API (app.bsky.feed.searchPosts on api.bsky.app), used without login. Its robots.txt says "Crawling the public parts of the API is allowed" and asks for no more than a handful of concurrent requests; this actor sends one at a time and backs off on HTTP 429. Not affiliated with Bluesky.
  • Search is Bluesky's own full-text search: phrase and hashtag queries work as on bsky.app. Bluesky limits deep pagination, so a very broad query over a long window may return fewer posts than maxPosts; narrow the window or add queries.
  • Privacy: only public posts, their links and public handles are returned; no follower lists, profile details or emails. Posts by accounts that opted out of logged-out visibility are skipped. Monitor mode stores only hashed post IDs. Please respect deletions when you store or republish posts.
  • Bluesky has switched keyless search off before; if it refuses requests the run says so in a free status row and does not fail.
  • Respects your run budget: set a maximum total charge and the run stops cleanly at the cap, with nothing charged twice. A run with no matches returns one free status row explaining why.

Use it from code

Run the actor through the Apify API with the input above.

cURL

curl -X POST "https://api.apify.com/v2/acts/actor-forge~bluesky-posts-search/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"keywords": ["openai"], "maxPosts": 10, "sinceHours": 168}'

JavaScript (Node.js)

// Node.js 18+ (built-in fetch). Set APIFY_TOKEN in your environment.
const input = {
  "keywords": [
    "openai"
  ],
  "maxPosts": 10,
  "sinceHours": 168
};

const res = await fetch(
  "https://api.apify.com/v2/acts/actor-forge~bluesky-posts-search/run-sync-get-dataset-items",
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.APIFY_TOKEN}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(input),
  }
);
const items = await res.json();
console.log(items.length, items[0]);

Python

# pip install apify-client   (set APIFY_TOKEN in your environment)
import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run_input = {
    "keywords": [
        "openai"
    ],
    "maxPosts": 10,
    "sinceHours": 168
}

run = client.actor("actor-forge/bluesky-posts-search").call(run_input=run_input)
for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item)

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.
