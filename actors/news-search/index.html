News Search - Global News by Keyword, Google News Alternative

Search news articles from the last 72 hours worldwide by keyword, source domain, country, language or theme, using the GDELT Project's open 15-minute feeds. Each article: URL, title, source, time, tone, themes, locations, organisations and image. No API key. $1.20 per 1,000 articles.

What it does

A news search API for the whole world's news, without Google News scraping or an API key. Give it keywords (a company, a product, a topic, a person in the news) and it returns matching news articles from the last 1 to 72 hours, newest first: article URL, page title, source domain, the time the article was seen (15-minute resolution), language, tone and sentiment, GDELT themes, locations and countries mentioned, organisations, lead image and which keywords matched. Filter by source domain (e.g. only reuters.com and bbc.co.uk, or exclude sites), country mentioned, language (English plus about 65 translated languages: German, French, Spanish, Chinese, Arabic, Russian, Japanese and more), GDELT theme and sentiment. Switch on monitor mode for scheduled runs and each run returns only articles newer than the last one, which makes it a cheap news monitoring and brand mention feed. Use it for media monitoring, PR and brand tracking, market and competitor news, financial news signals, news datasets for AI agents and RAG pipelines, and as a Google News alternative that works from any server. Chain it with Website to Markdown when you need the full article text. The data comes from the open GDELT Project 15-minute GKG files, which GDELT licenses for unlimited commercial use with attribution; every row carries a source credit. $1.20 per 1,000 articles, with no compute bill on top. Runs that find nothing return a free status row instead of failing.

Limits and honest notes

  • Data: the GDELT Project's open GKG 2.1 files (https://www.gdeltproject.org/), published every 15 minutes and licensed for unlimited use with attribution. Every row has source "GDELT Project (https://www.gdeltproject.org/)"; please keep that credit when you republish the data. Not affiliated with GDELT or Google.
  • Keywords match whole words in the title, the URL, the organisations GDELT extracted and the names mentioned in the article. They are not matched against the full article text, so recall is lower than a full-text search engine. Use several related keywords (e.g. "artificial intelligence" and "AI") for better coverage.
  • publishedAt is the 15-minute GDELT batch in which the article was first seen (usually within 15 minutes of publication), not the publisher's own timestamp. publishedAtPrecision says so on every row.
  • Window: up to 72 hours back for English-language news, up to 24 hours for the translated feed (about 65 languages; titles stay in the original language). GDELT sometimes skips or delays a batch; those are reported as missing in the run summary and skipped.
  • Coverage is what GDELT monitors: tens of thousands of news sites worldwide, roughly 1,000 English and 3,000 translated articles per 15 minutes. There is no "top stories" ranking: results are newest first.
  • No article bodies. Chain Website to Markdown on the URLs if you need full text.
  • Countries are matched by English country name in GDELT's location data ("Germany", "United Kingdom"); the locations field also gives GDELT's FIPS country codes and coordinates.
  • People names are off by default. Switching on includePeople adds names of people mentioned (mostly public figures); do not use them to profile individuals.
  • Respects your run budget: set a maximum total charge and the run stops cleanly at the cap, with nothing charged twice. A run with no matches returns one free status row explaining why.

Use it from code

Run the actor through the Apify API with the input above.

cURL

curl -X POST "https://api.apify.com/v2/acts/actor-forge~news-search/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"keywords": ["artificial intelligence"], "lookbackHours": 1, "maxArticles": 20}'

JavaScript (Node.js)

// Node.js 18+ (built-in fetch). Set APIFY_TOKEN in your environment.
const input = {
  "keywords": [
    "artificial intelligence"
  ],
  "lookbackHours": 1,
  "maxArticles": 20
};

const res = await fetch(
  "https://api.apify.com/v2/acts/actor-forge~news-search/run-sync-get-dataset-items",
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.APIFY_TOKEN}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(input),
  }
);
const items = await res.json();
console.log(items.length, items[0]);

Python

# pip install apify-client   (set APIFY_TOKEN in your environment)
import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run_input = {
    "keywords": [
        "artificial intelligence"
    ],
    "lookbackHours": 1,
    "maxArticles": 20
}

run = client.actor("actor-forge/news-search").call(run_input=run_input)
for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item)

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.
