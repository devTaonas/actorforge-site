E-commerce Product Scraper — Any Store URL, Price & Stock

Scrape product data from any store URL: name, brand, SKU, GTIN, price, sale price, currency, stock, variants, images and rating, from schema.org JSON-LD, microdata, OpenGraph and Shopify/WooCommerce fast paths. Price monitoring with change alerts. $2 per 1,000 products.

What it does

An e-commerce scraper for product data from any store. Give it product page URLs from independent and direct-to-consumer shops, on Shopify, WooCommerce, BigCommerce, Magento, PrestaShop, Shopware, Wix, Squarespace or a custom site, and you get one clean row per product: name, brand, SKU, GTIN/MPN, price, sale price and regular price, currency, stock status, variants (size, colour, SKU, price and stock for each), images, description, category, aggregate rating and review count, and the seller. This product scraper reads the structured data stores publish for Google Shopping. It tries schema.org JSON-LD first (including @graph, offers arrays, AggregateOffer and ProductGroup variants), then microdata, then the store's public product JSON (Shopify's /products/{handle}.js and the WooCommerce Store API), and finally OpenGraph product tags. Each row says which platform was detected and where the price came from. It does not need per-site selectors. For price monitoring, set a monitorName and schedule the run: every row gets a changed object (new product, price changed, stock changed, previous values), and onlyChanges outputs and charges only the products that changed. Turn on discover to start from a category page, a homepage or a sitemap.xml instead of product URLs. It uses plain HTTP at 512 MB with an honest user agent, the store's own robots.txt and at most 2 requests at a time per store. $2 per 1,000 products, which is a third of the big e-commerce tools. Blocked, disallowed and non-product pages are free. Built for the long tail, not Amazon: it uses no proxies, unblockers or CAPTCHA solving, so Amazon, Walmart and other heavily protected retailers will mostly come back as free blocked rows.

Limits and honest notes

  • Built for independent and direct-to-consumer stores. There are no proxies, unblockers or CAPTCHA solving. A 403, 429 or bot challenge (Cloudflare, DataDome, PerimeterX, Akamai, Imperva and others) stops that store for the rest of the run, with no retries, and its remaining URLs become free blocked rows. Amazon, Walmart, Target, eBay and similar big retailers will mostly be blocked or disallowed. Use a dedicated marketplace actor for those.
  • Every store's robots.txt is read first and obeyed for our user agent (ActorForge-ProductScraper), including Crawl-delay (capped at 10 s). A disallowed product page gives a free robots-disallowed row and is never requested.
  • Plain HTTP only: no JavaScript is run. Stores that render products only in the browser and publish no JSON-LD, microdata, OpenGraph product tags or Shopify/WooCommerce product JSON come back as free not-product rows.
  • Prices are what the store publishes in its structured data, usually in the store's base currency. Prices for a specific country or logged-in customer, tax-inclusive variants and cart discounts are not visible. priceSource says where each price came from, and some stores' JSON-LD can lag behind the visible price.
  • Variants come from offers arrays, ProductGroup.hasVariant, Shopify's /products/{handle}.js and the WooCommerce Store API. WooCommerce variation prices are not in that API, so those variants list their options without a price. Rows carry at most 250 variants and 20 images, and the description is capped at 2,000 characters of plain text.
  • Ratings are aggregate only (ratingValue, reviewCount). Review text, reviewer names and any other personal data are never read into the output. Person sellers on marketplaces are dropped; only organisation sellers are kept.
  • discover follows product sitemaps (sitemap indexes, gzip, robots.txt Sitemap: lines) and product links on category pages, up to maxProducts URLs. It reads at most 25 sitemaps per starting URL and does not page through paginated category pages.
  • Monitor state is stored in your own named key-value store products-<monitorName> and keyed by URL. Use a separate monitor name for each product list. A change cut off by the spend limit is reported on the next run.
  • The run's spend limit is respected: each product is charged just before it is delivered, and the run stops cleanly when the limit is reached.

Use it from code

Run the actor through the Apify API with the input above.

cURL

curl -X POST "https://api.apify.com/v2/acts/actor-forge~ecommerce-product-scraper/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"urls": ["https://www.allbirds.com/products/mens-tree-runners", "https://cornerstone-light-demo.mybigcommerce.com/orbit-terrarium-large/"]}'

JavaScript (Node.js)

// Node.js 18+ (built-in fetch). Set APIFY_TOKEN in your environment.
const input = {
  "urls": [
    "https://www.allbirds.com/products/mens-tree-runners",
    "https://cornerstone-light-demo.mybigcommerce.com/orbit-terrarium-large/"
  ]
};

const res = await fetch(
  "https://api.apify.com/v2/acts/actor-forge~ecommerce-product-scraper/run-sync-get-dataset-items",
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.APIFY_TOKEN}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(input),
  }
);
const items = await res.json();
console.log(items.length, items[0]);

Python

# pip install apify-client   (set APIFY_TOKEN in your environment)
import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run_input = {
    "urls": [
        "https://www.allbirds.com/products/mens-tree-runners",
        "https://cornerstone-light-demo.mybigcommerce.com/orbit-terrarium-large/"
    ]
}

run = client.actor("actor-forge/ecommerce-product-scraper").call(run_input=run_input)
for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item)

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.
