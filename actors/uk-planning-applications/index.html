UK Planning Applications Scraper: Weekly Lists from 15 Councils

Each council's official weekly list of validated or decided planning applications, unified into one clean dataset with a link to every application.

Run on Apify →See pricing

What it does

Planning applications are one of the few public signals that building work is about to happen. The trouble is that every council publishes them on its own portal, with its own search forms and weekly lists, so checking a dozen areas each Monday is a morning's work.

This actor reads the weekly lists from 15 UK council planning portals (all verified Idox portals) and returns them as one dataset: council, application reference, proposal text, site address, status, received and validated dates, and a deep link to the council's own application page. Choose validated for newly accepted applications or decided for fresh decisions, and how many recent weeks to fetch.

Validated applications are a proven lead source for builders, scaffolders, architects and other trades; decisions are useful to developers, land sourcers and analysts. Applicant and agent personal details are deliberately not collected, and the actor is polite to councils at no more than one request per second per portal.

How it works

  1. You pick councils from the list (or leave it empty for all 15), the list type (validated or decided) and how many weeks back to go.
  2. For each council the actor opens the portal's weekly list and reads up to 20 result pages, about 200 applications at the usual page size.
  3. Rows are normalised into one schema with council, reference, proposal, address, status, dates and the application URL.
  4. If one council portal is down, that council is flagged in the run log and exit message and the run carries on with the rest.
  5. The run stops at maxResults or your spend limit, and you are charged only for applications delivered.

Limits and honest notes

  • Covers 15 councils at launch (listed in the input dropdown) — all verified Idox portals; a portal that fails is flagged in the run log and exit message, never silently dropped.
  • Each council's weekly list is read up to 20 result pages (about 200 applications at the portals' usual page size), which covers a normal week for most councils; an unusually busy week at a large council can be cut off at that point.
  • Weekly-list data as published by each council: reference, proposal, site address, status, received/validated dates, deep link. Applicant and agent personal details are deliberately not collected.
  • A council portal outage degrades that council only — the run reports it and continues with the rest.
  • Weekly lists roll over on Mondays — early in the week the newest list can be nearly empty. Set weeksBack to 2 if you always want a full week of applications.
  • Polite by design: ≤1 request/second per council portal.
  • Respects your run budget: set a maximum total charge and the actor stops cleanly at the cap.

FAQ

Which UK councils are covered?

Isle of Wight, Durham, Barnet (London), Leeds, York, Cornwall, Trafford, Gateshead, Bradford, Aberdeen, Aberdeenshire, Sunderland, Southampton, Greater Cambridge and Oxford. Leave councils empty to fetch all 15.

What is the difference between validated and decided applications?

Validated means the council has accepted the application as complete and it is now being considered, which is the lead-generation signal that work may be coming. Decided lists applications that have just received a decision.

Why does my run return very few applications early in the week?

Weekly lists roll over on Mondays, so the newest list can be nearly empty at the start of the week. Set weeksBack to 2 if you always want at least one full week.

Does it include the applicant's name or contact details?

No. Applicant and agent personal details are deliberately not collected. You get the reference, proposal, site address, status, dates and a link to the council's page.

Can a busy council's week be cut off?

Possibly. Each weekly list is read up to 20 result pages, about 200 applications, which covers a normal week for most councils. An unusually busy week at a large council can be truncated at that point.

How much does a weekly run cost?

$0.003 per application. A typical single-council week of about 25 applications costs around $0.08, and 1,000 applications cost $3.00.

Python

# pip install apify-client   (set APIFY_TOKEN in your environment)
import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run_input = {
    "councils": [
        "leeds",
        "bradford",
        "york"
    ],
    "weeksBack": 2,
    "dateType": "validated",
    "maxResults": 500
}

run = client.actor("actor-forge/uk-planning-applications").call(run_input=run_input)
for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item)

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.
