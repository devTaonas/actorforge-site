US Healthcare Provider Search — NPI Organizations & Leads

Search the official CMS NPI Registry for US healthcare organizations (clinics, hospitals, pharmacies, home health, dentists…) by specialty, city, state, ZIP or name, or look up NPIs: name, DBA, taxonomies, practice address, business phone. Beats the 1,200 cap. $0.70 per 1,000.

What it does

A US healthcare provider search for organisation leads, straight from the official CMS NPI Registry. Every US healthcare organisation that bills health plans has a National Provider Identifier (NPI), and the CMS NPPES registry publishes the organisation records as public data: hospitals, clinics, urgent care centres, pharmacies, dental practices, home health agencies, hospices, nursing facilities, labs, ambulance services, DME suppliers and more. Search by specialty or provider type (taxonomy text such as Urgent Care, Dentist, Home Health, or an exact NUCC taxonomy code), city, state or ZIP / ZIP prefix, and organisation name, or look up NPIs you already have, and get one clean row per organisation: NPI, legal name, DBA and other names, primary taxonomy and every taxonomy with its state licence, practice address and business phone/fax, mailing address, other practice locations, Medicaid and other identifiers, subpart and parent organisation, enumeration and last-updated dates, and the registry link. The registry only returns 1,200 results per search: this actor splits large searches automatically by state and ZIP prefix and de-duplicates by NPI, so you can pull every urgent care centre in Texas in one run. Use it for healthcare B2B prospecting (medical supplies, software, billing, staffing, marketing agencies), territory planning, provider network and directory building, and NPI verification. Organisations only (NPI-2): individual practitioners are deliberately left out. $0.70 per 1,000 providers, with no compute bill on top; problems return a free status row instead of failing.

Limits and honest notes

  • Responsible use: the data is public US government data, but you are responsible for how you contact organisations (TCPA, CAN-SPAM, state laws). This actor is not affiliated with, endorsed by or sponsored by CMS, HHS or NPPES. Data source: CMS NPPES NPI Registry (public US government data).
  • Organisations only. Searches always ask the registry for organisation NPIs (NPI-2). Individual practitioners (NPI-1: doctors, nurses, therapists) are personal data and are left out entirely, including in NPI lookups. The authorised official of each organisation is shown by title only; their name and direct phone are never output. Phone numbers are the organisation's business practice-location numbers as filed with CMS.
  • It calls the official keyless NPPES API (version 2.1), about 1.4 requests per second, 200 records per request, with an honest user agent (ActorForge-NPI), no login, cookies or proxies. NPPES limits queries per hour and asks bulk users to download its full monthly data file: a run stops after 1,200 requests (roughly 100,000+ records scanned), NPI lookups are limited to 200 per run, and Max providers to 20,000.
  • Search behaviour follows the registry: specialty text matches taxonomy names ("Hospital" also matches "Hospitalist", so prefer "General Acute Care Hospital"), organisation names are prefix matches, and only active NPIs are returned. With Primary taxonomy only (default) an organisation is kept only if its primary taxonomy matches. Splitting uses USPS ZIP prefixes per state (and the ZIPs seen in a city's results), so a few records filed under an unusual ZIP may be missed.
  • The registry is updated daily by providers themselves; addresses and phones can be out of date, and an NPI does not prove a licence or credential. If the registry refuses a request (for example the hourly limit), the run stops, keeps the rows already delivered and adds a free status row. Set a maximum total charge and the run stops cleanly at the cap; a run with no results returns one free status row.

Use it from code

Run the actor through the Apify API with the input above.

cURL

curl -X POST "https://api.apify.com/v2/acts/actor-forge~us-healthcare-providers/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"taxonomies": ["Urgent Care"], "cities": ["Houston, TX"], "maxItems": 20}'

const items = await res.json();
console.log(items.length, items[0]);

Python

# pip install apify-client   (set APIFY_TOKEN in your environment)
import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run_input = {
    "taxonomies": [
        "Urgent Care"
    ],
    "cities": [
        "Houston, TX"
    ],
    "maxItems": 20
}

run = client.actor("actor-forge/us-healthcare-providers").call(run_input=run_input)
for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item)

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.
