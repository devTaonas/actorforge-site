Career Page Jobs by Company Name or Domain — Any ATS

Give company names or domains: the actor finds each careers page, detects the ATS (Greenhouse, Lever, Ashby, Workday, Workable and more) and returns every open job in one schema, plus a summary row per company. $0.015 per company with jobs; not-found is free.

Run on Apify →See pricing

What it does

Get jobs by company: paste company names or domains and get back every open role from each company's own careers page, in one clean schema, without knowing which applicant tracking system they use. This company career page scraper fetches the homepage and careers pages (respecting robots.txt), does ATS detection on the links and embeds it finds (Greenhouse, Lever, Ashby, Workday, Workable, Recruitee, Teamtailor, Personio, BambooHR; SmartRecruiters, iCIMS, Jobvite, BreezyHR, JazzHR, Rippling, Taleo and SuccessFactors are flagged), falls back to verified board-name guesses on the Greenhouse, Lever, Ashby and Workday public APIs, then reads the jobs from the ATS's own public feed: title, department, team, location, remote/hybrid/onsite, employment type, salary where published, posted date and apply link, with an optional full description. Every company also gets a summary row (found / no-ats-found / unsupported-ats / blocked / not-found, the ATS, the board URL and the job count), so the run works as a hiring-signals feed for sales teams, Clay tables and AI agents: who is hiring, how many roles, on which ATS. In our 27-company test, 21 (78%) were found, including Stripe, Figma, Notion, OpenAI, Salesforce, Adobe and NVIDIA. $0.015 per company with jobs (up to 500 jobs included), about a third of the leading company-lookup actor ($0.045); companies with no ATS, an unsupported ATS, no matching jobs or an unresolvable name are free.

Limits and honest notes

  • Jobs are read from Greenhouse, Lever, Ashby, Workday, Workable, Recruitee, Teamtailor, Personio and BambooHR public feeds. SmartRecruiters (its robots.txt disallows crawling), iCIMS, Jobvite, BreezyHR, JazzHR, Rippling, Taleo and SuccessFactors are detected and reported as unsupported-ats (free). Fully in-house careers sites (e.g. HubSpot, Shopify) return no-ats-found.
  • Names are resolved conservatively: only <name>.com (and <name-with-hyphens>.com) are tried, and only accepted when the homepage title or og:site_name contains the name. No search engines are used. If that fails, a Greenhouse/Lever/Ashby board whose name equals the input exactly is accepted; otherwise the row is not-found. Passing domains gives the best hit rate.
  • Detection reads static HTML: the homepage, up to 3 careers links found on it, and /careers, /jobs, /company/careers, /about/careers. Careers pages that load their job widget only from JavaScript bundles may be missed; the fallback then guesses the board slug from the domain (e.g. datadoghq.com → greenhouse:datadog) and keeps it only if the board's company name matches the website.
  • Workday fallback: the tenant is guessed as the domain stem on the wd1/3/5/10/12/103 data centres, and the main external careers site is taken from the tenant's robots.txt. Workday reads one detail request per job, at most 2 requests at a time per host, so 500 Workday jobs take about 2-3 minutes.
  • Workday and some company sites rate-limit shared cloud IPs (HTTP 429). The actor backs off and retries once (honouring Retry-After, up to 30 s); if the site still refuses, the company row is failed with a note and is not charged, and the remaining companies on that host are skipped as free rows instead of pushing harder. A 403 bot wall is treated the same way.
  • Sites behind bot protection (Cloudflare challenges, 403s) are reported as blocked unless the slug fallback finds the board. robots.txt is respected for every site page and for Workday tenants.
  • One board per company: the most-linked supported board. Companies with several boards (e.g. separate intern sites) return the main one.
  • Only public job postings are returned. Recruiter names, emails, phone numbers and application-form fields are never collected.
  • The run's spend limit is respected: each company is charged once, before its first job row; when the limit is reached no further companies are charged or delivered.

Python

# pip install apify-client   (set APIFY_TOKEN in your environment)
import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run_input = {
    "companies": [
        "figma.com",
        "notion.com",
        "Stripe",
        "salesforce.com"
    ]
}

run = client.actor("actor-forge/career-page-jobs").call(run_input=run_input)
for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item)

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.
