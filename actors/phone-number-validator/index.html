Phone Number Validator - Bulk E.164 Formatting & Line Type

Validate and format phone numbers in bulk, offline with Google's libphonenumber data: valid/possible, E.164, international and national formats, country, calling code, extension and line type (mobile, fixed line, toll-free, VoIP). From a list, CSV/Excel or dataset column. $0.30 per 1,000.

Run on Apify →See pricing

What it does

Clean and standardise phone numbers in bulk before they hit your CRM, dialer or SMS tool. Paste a list, or point it at a CSV / Excel / JSON file or an Apify dataset column (for example the output of a business-leads scrape), and get one row per number: valid?, possible?, E.164 (+14155552671), international and national formats, tel: URI, ISO country and country name, calling code, extension and line type (mobile, fixed line, toll-free, premium rate, VoIP, shared cost…), plus a plain-English reason when a number is invalid. Validation runs offline against Google's libphonenumber numbering-plan data (via libphonenumber-js), the same rules Android and Google use, so it is fast, private and cheap: no number is sent to any third-party service, and nothing is looked up about who owns it. Use it for CRM and lead-list hygiene, form and signup validation, normalising numbers to E.164 for Twilio, WhatsApp Business or HubSpot, routing mobile vs landline numbers, and deduplicating contact lists. Numbers without a + prefix use your default country, or a per-row country column. $0.30 per 1,000 numbers; duplicates and empty cells are free.

Limits and honest notes

  • Offline validation checks a number against its country's numbering plan only. It cannot tell whether a number is currently assigned, switched on or reachable, and it does not identify the carrier after number porting. "valid" means the number is correctly formed and in an allocated range.
  • No lookups of people: the actor never queries who owns a number and returns no personal data beyond the number you supplied. It is meant for business uses such as CRM hygiene and form validation; process personal phone numbers only with a lawful basis.
  • Line type comes from the numbering plan: in the US, Canada and some other countries mobile and fixed-line ranges overlap, so you get fixed_line_or_mobile.
  • Numbering-plan data is Google's libphonenumber metadata as shipped with libphonenumber-js at build time; plans change a few times a year and the actor is rebuilt with updates.
  • Files are downloaded once (up to 50 MB) and private or internal network addresses are refused at every redirect hop. Datasets are read only when you pick them in the Dataset field (limited permissions).

Use it from code

Run the actor through the Apify API with the input above.

cURL

curl -X POST "https://api.apify.com/v2/acts/actor-forge~phone-number-validator/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"phoneNumbers": ["+44 20 7946 0958", "(415) 555-2671"], "defaultCountry": "US"}'

JavaScript (Node.js)

// Node.js 18+ (built-in fetch). Set APIFY_TOKEN in your environment.
const input = {
  "phoneNumbers": [
    "+44 20 7946 0958",
    "(415) 555-2671"
  ],
  "defaultCountry": "US"
};

const res = await fetch(
  "https://api.apify.com/v2/acts/actor-forge~phone-number-validator/run-sync-get-dataset-items",
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.APIFY_TOKEN}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(input),
  }
);
const items = await res.json();
console.log(items.length, items[0]);

Python

# pip install apify-client   (set APIFY_TOKEN in your environment)
import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run_input = {
    "phoneNumbers": [
        "+44 20 7946 0958",
        "(415) 555-2671"
    ],
    "defaultCountry": "US"
}

run = client.actor("actor-forge/phone-number-validator").call(run_input=run_input)
for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item)

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.
