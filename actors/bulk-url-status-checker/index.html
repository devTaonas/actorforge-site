Bulk URL Status Checker — HTTP Codes & Redirect Chains

Paste a list of URLs and get each one's HTTP status code, final URL after redirects, the full redirect chain, response time and error type (404, 5xx, DNS, timeout, SSL). No crawling: exactly the URLs you give. $0.20 per 1,000 URLs.

Run on Apify →See pricing

What it does

Check a list of URLs in bulk and get, for every URL, the HTTP status code, the final URL after redirects, the full redirect chain (each hop with its 301/302/307/308 status), the response time and, when it fails, the error type (404, 410, 5xx, DNS failure, timeout, SSL error, redirect loop). Exactly the URLs you paste are checked: nothing is crawled and no links are followed, so 10,000 URLs cost the same as 10,000 checks.

Use it for site migrations and redirect QA (do the old URLs land on the right new pages with a single 301?), cleaning link lists and backlink exports, checking affiliate, ad or QR-code destinations, monitoring a set of key pages on a schedule, or validating URLs in a spreadsheet before an import.

Limits and honest notes

  • Checks only the URLs you give: it does not crawl pages or check the links on them. To find broken links across a whole website, use Broken Link Checker.
  • Some sites refuse automated requests: LinkedIn answers 999, others answer 403 or 429 or show a Cloudflare challenge. Those links usually work in a browser, so they are reported as 'blocked' (status kept) instead of broken. Hide them with 'Report bot-blocked links' or skip them with 'Ignore links matching'.
  • Each unique link is checked once with a HEAD request; when a server refuses HEAD or answers a common error status (400, 403, 404, 405, 410, 5xx…) or drops the connection, the result is confirmed with GET before it is called broken. Redirects are followed up to 10 hops, with the full chain recorded. Each request times out after 20 seconds.
  • Polite by design: at most 2 requests at a time per host, and a 429 'Too Many Requests' pauses that host for its Retry-After. Very link-heavy external hosts (GitHub, for example) therefore take a while to check.
  • Redirects are followed up to 10 hops; a longer chain or a loop is reported as broken (too-many-redirects). JavaScript or meta-refresh redirects are not followed.
  • Links to internal network addresses (localhost, private IPs, cloud metadata) are never requested and never charged.
  • Respects your run budget: set a maximum total charge and the run stops cleanly at the cap and reports everything checked so far.

Use it from code

Run the actor through the Apify API with the input above.

cURL

curl -X POST "https://api.apify.com/v2/acts/actor-forge~bulk-url-status-checker/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"startUrls": ["http://apify.com", "https://httpbin.org/status/404", "https://example.com"]}'

JavaScript (Node.js)

// Node.js 18+ (built-in fetch). Set APIFY_TOKEN in your environment.
const input = {
  "startUrls": [
    "http://apify.com",
    "https://httpbin.org/status/404",
    "https://example.com"
  ]
};

const res = await fetch(
  "https://api.apify.com/v2/acts/actor-forge~bulk-url-status-checker/run-sync-get-dataset-items",
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.APIFY_TOKEN}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(input),
  }
);
const items = await res.json();
console.log(items.length, items[0]);

Python

# pip install apify-client   (set APIFY_TOKEN in your environment)
import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run_input = {
    "startUrls": [
        "http://apify.com",
        "https://httpbin.org/status/404",
        "https://example.com"
    ]
}

run = client.actor("actor-forge/bulk-url-status-checker").call(run_input=run_input)
for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item)

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.
