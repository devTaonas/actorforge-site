Wikipedia Scraper: Articles, Full Text, Wikidata & Pageviews

Wikipedia articles in any language via the official MediaWiki API: intro or full plain text, short description, Wikidata ID, coordinates, image, categories, last edit and 30-day pageviews. Titles, URLs or search. CC BY-SA attribution included. $0.60 per 1,000 articles.

Run on Apify →See pricing

What it does

Wikipedia data through Wikipedia's own API, in any language. Give it article titles, Wikipedia URLs or search terms and get one clean row per article: title, link, short description, the intro as plain text (or the full article text with word count), Wikidata ID, coordinates for places, lead image, categories, last edit time and revision, page size, a disambiguation flag, the redirect it came from, and optionally pageviews over the last 30 days. Every row carries the CC BY-SA 4.0 licence and a ready-made attribution line. Use it for knowledge bases and RAG/LLM datasets, entity enrichment and linking (via Wikidata IDs), SEO and content research, popularity tracking with pageviews, and education projects. $0.60 per 1,000 articles, with no compute bill on top; problems return a free status row instead of failing.

Limits and honest notes

  • Attribution and licence: Wikipedia text is available under the Creative Commons Attribution-ShareAlike 4.0 licence (CC BY-SA 4.0). If you republish it, credit Wikipedia and link the article (each row has an attribution line and the url), and share adaptations under the same licence. Images have their own licences on Wikimedia Commons. This actor is not affiliated with, endorsed by or sponsored by the Wikimedia Foundation.
  • Responsible use: it uses only the official MediaWiki Action API and the Wikimedia pageviews API, following Wikimedia's API etiquette: an identifying user agent with a contact URL (ActorForge-Wikipedia), one request at a time with at least 0.5 s between requests, batches of 20 titles, and maxlag=5 (it pauses when Wikimedia's servers are busy). There is no page scraping, no login and no proxies.
  • Biographies of living people are returned as Wikipedia publishes them; follow data-protection law if you combine them with other personal data.
  • If Wikimedia refuses a request or rate-limits the run, the run stops, keeps the articles already delivered and adds a free status row. Respects your run budget: set a maximum total charge and the run stops cleanly at the cap. Missing articles return a free status row.

Use it from code

Run the actor through the Apify API with the input above.

cURL

curl -X POST "https://api.apify.com/v2/acts/actor-forge~wikipedia-scraper/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"articles": ["Web scraping", "Paris"]}'

JavaScript (Node.js)

// Node.js 18+ (built-in fetch). Set APIFY_TOKEN in your environment.
const input = {
  "articles": [
    "Web scraping",
    "Paris"
  ]
};

const res = await fetch(
  "https://api.apify.com/v2/acts/actor-forge~wikipedia-scraper/run-sync-get-dataset-items",
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.APIFY_TOKEN}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(input),
  }
);
const items = await res.json();
console.log(items.length, items[0]);

Python

# pip install apify-client   (set APIFY_TOKEN in your environment)
import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run_input = {
    "articles": [
        "Web scraping",
        "Paris"
    ]
}

run = client.actor("actor-forge/wikipedia-scraper").call(run_input=run_input)
for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item)

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.
