Google Play Scraper — App Details, Installs, Ratings & Reviews

Scrape Google Play apps by package name or URL: installs, rating histogram, price, version, developer, screenshots, similar apps and up to 20 anonymised reviews per app. Many countries, monitoring mode. No keyword search. $0.80 per 1,000 apps.

What it does

Scrape Google Play app details by package name or URL for ASO (app store optimization), competitor tracking, market research and app-intelligence dashboards. Give it package names (com.spotify.music) or play.google.com URLs, pick countries and a language, and get one row per app and country: title, developer (name, id, website, company support mailbox), category and genres, star rating, ratings count, rating histogram, installs range and exact install count, price and currency, in-app purchases, ads, content rating, release and last-update dates, version, minimum Android version, description, release notes, icon, screenshots, similar apps and more by this developer. Reviews are on by default: the Google Play reviews shown on the public app page, with rating, text, date, thumbs-up, app version and developer reply, with reviewer names, avatars and user ids stripped (GDPR-safe). Two limits, stated up front: there is no keyword search (Google Play's robots.txt disallows /store/search, so you give package names or URLs), and reviews are capped at 20 per app, country and language, the "most relevant" set on the public page, so this is not a tool for deep review history. Schedule it with *Only new reviews since last run* to build history and watch ratings and versions over time. Plain HTTP, 256 MB, no browser. $0.80 per 1,000 apps, about a third of the app-details leader; reviews $0.04 per 1,000.

Limits and honest notes

  • No keyword search. Google Play's robots.txt disallows /store/search, so apps are given by package name or play.google.com URL.
  • Reviews: at most 20 per app, country and language — the "most relevant" reviews shown on the public app page. Google's paging endpoint (/_/PlayStoreUi/data/batchexecute) and /store/getreviews are disallowed by its robots.txt, so there is no deep history and no newest-first sort. Scheduled runs with *Only new reviews since last run* build up history over time.
  • Reviewer names, avatars and user ids are never returned, and developer e-mails are kept only when they are company mailboxes (support@, help@ … on the company's own domain). Review text is returned as written.
  • Google Play does not publish app size on the web any more, so size is null. Fields Google Play does not provide are null.
  • Google Play only in this listing. For Apple App Store apps and Apple's top charts, use App Store & Google Play Scraper.
  • Plain HTTP from Apify's servers, at most 2 requests at a time, with pauses. If Google Play shows a CAPTCHA, an 'unusual traffic' page or keeps answering 429/403, the actor stops asking Google Play for the rest of the run and returns free error rows for the skipped apps. No proxies, no CAPTCHA solving.
  • robots.txt is re-checked at the start of every run; if Google Play ever disallows the pages used here, the run returns free error rows.
  • Error rows (app not found in a country, store blocked) are free. Respects your run budget: set a maximum total charge and the actor stops cleanly at the cap.

Use it from code

Run the actor through the Apify API with the input above.

cURL

curl -X POST "https://api.apify.com/v2/acts/actor-forge~google-play-scraper/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"apps": ["com.spotify.music", "com.whatsapp"], "countries": ["us"], "language": "en", "maxReviewsPerApp": 5}'

const items = await res.json();
console.log(items.length, items[0]);

client = ApifyClient(os.environ["APIFY_TOKEN"])
run_input = {

        "com.spotify.music",
        "com.whatsapp"
    ],
    "countries": [

for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item)

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.
