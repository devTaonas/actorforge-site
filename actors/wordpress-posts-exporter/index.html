WordPress Posts Exporter — Any WP Site via REST API (wp-json)

Export every post, page, category and tag from any WordPress site via its public REST API: title, dates, author, categories, tags, excerpt, full HTML and text, featured image. Whole back catalogue, not just the feed. Date and search filters. $0.70 per 1,000 items.

Run on Apify →See pricing

What it does

Export a whole WordPress site's content: every post, page, category and tag. Paste any WordPress site URL (a sub-directory install like example.com/blog works too) and the actor finds its public REST API (wp-json) and pages through the entire back catalogue, not just the 10 newest items an RSS feed shows. Each post comes back as one clean row: title, link, slug, publish and modified dates in ISO 8601 (UTC), author name, category and tag names (plus their ids), a plain-text excerpt, the full body as HTML and plain text, word count, featured image URL, sticky and password-protected flags. Pages add parent id and menu order; categories and tags add their description, post count and parent. Filter by publish date range and search text, take newest or oldest first, and cap items per site. Use it for content migrations and backups, SEO content audits, competitor content analysis, training data and RAG pipelines, editorial calendars and archive research. No API key, no login, no browser. $0.70 per 1,000 items exported; sites whose REST API is switched off, or whose robots.txt disallows it, get one free row explaining why.

Limits and honest notes

  • Works with WordPress sites whose REST API is publicly readable, which is the WordPress default. Sites that switched it off, require a login for it, or block it with a security plugin or firewall get one free row with the reason (for example rest_login_required). Nothing is charged for them.
  • robots.txt is respected (RFC 9309). If a site disallows /wp-json/, it is skipped with a free 'robots-disallowed' row, and the actor does not fall back to the ?rest_route= address. If a site's robots.txt can't be fetched (HTTP 5xx or a network error, after one retry), that site is skipped too. Crawl-delay is honoured up to 10 seconds between requests, so a large site with a long crawl delay takes a few minutes.
  • Exports public, published content only: no drafts, private posts, comments, media library or user accounts. The author field is the public byline name only; author bios, emails and profile URLs are never exported.
  • Password-protected posts are listed with their title, date and link, but no excerpt or body (isPasswordProtected is true).
  • Custom post types (products, events, portfolio items) and custom taxonomies are not exported; only posts, pages, categories and tags.
  • Full content is the HTML WordPress renders for the post body, capped at 200,000 characters per item. Shortcodes from page builders may appear as rendered markup. Excerpts are plain text up to 1,000 characters.
  • Dates are taken from WordPress's GMT fields and returned in UTC. The date filters are applied by WordPress and are read in the site's own time zone.
  • The search filter uses the site's built-in WordPress search, so results match what the site's own search box returns.
  • Respects your run budget: set a maximum total charge and the run stops cleanly at the cap, with no item charged twice.

Use it from code

Run the actor through the Apify API with the input above.

cURL

curl -X POST "https://api.apify.com/v2/acts/actor-forge~wordpress-posts-exporter/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"siteUrls": ["https://wordpress.org/news"], "contentTypes": ["posts"], "maxItemsPerType": 20}'

JavaScript (Node.js)

// Node.js 18+ (built-in fetch). Set APIFY_TOKEN in your environment.
const input = {
  "siteUrls": [
    "https://wordpress.org/news"
  ],
  "contentTypes": [
    "posts"
  ],
  "maxItemsPerType": 20
};

const res = await fetch(
  "https://api.apify.com/v2/acts/actor-forge~wordpress-posts-exporter/run-sync-get-dataset-items",
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.APIFY_TOKEN}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(input),
  }
);
const items = await res.json();
console.log(items.length, items[0]);

Python

# pip install apify-client   (set APIFY_TOKEN in your environment)
import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run_input = {
    "siteUrls": [
        "https://wordpress.org/news"
    ],
    "contentTypes": [
        "posts"
    ],
    "maxItemsPerType": 20
}

run = client.actor("actor-forge/wordpress-posts-exporter").call(run_input=run_input)
for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item)

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.
