Website Screenshot API — Full Page, Mobile, Element & PDF

Bulk website screenshots and PDFs: viewport, full-page or element, as PNG, JPEG or PDF, on desktop, tablet or mobile. Hides cookie banners, supports dark mode, returns direct file links. $1 per 1,000 screenshots, $2 per 1,000 full-page/PDF.

Run on Apify →See pricing

What it does

Take website screenshots and PDFs at scale with one API call. Give it a list of URLs. You get back a viewport, full-page or single-element capture of each page as PNG, JPEG or PDF, rendered on desktop, laptop, tablet or mobile (real iPhone/iPad viewports and user agents), with cookie banners hidden and optional dark mode. Every capture is saved to storage and returned as a direct download link that works without an API token, so it's easy to hand to AI agents, Zapier/Make, or your own app. Use it for visual monitoring and archiving, website thumbnails and link previews, SEO and competitor audits, QA and regression snapshots, compliance evidence, or as a 'look at this page' tool for AI agents. Pages that fail to load (blocked, 4xx/5xx, nothing rendered) are reported with the reason and never charged.

Limits and honest notes

  • Full-page captures are capped at 16,000 device pixels tall (Chrome's practical rasterisation limit): 16,000 CSS px on desktop/laptop, 8,000 on tablet/mobile (2×). Longer pages are captured from the top down to that height.
  • Full-page mobile/tablet captures render at 2× (not 3×) to stay within that limit. Viewport captures use the device's native scale.
  • Sites that block automated browsers (e.g. some news paywalls returning HTTP 403) can't be captured. They come back as error rows and are not charged.
  • Video and audio are not loaded (they never appear in a still image), which makes captures faster and leaner.
  • Cookie-banner hiding covers the major consent platforms (OneTrust, Cookiebot, Usercentrics, Didomi, Quantcast, TrustArc and more). Custom in-house banners may still appear.
  • For security, internal and private addresses (localhost, 10.x, 192.168.x, cloud metadata endpoints) are refused.
  • Download links are signed and work without an API token for as long as the run's storage is retained (per your Apify plan).
  • Respects your run budget: set a maximum total charge and the actor stops cleanly at the cap.

Use it from code

Run the actor through the Apify API with the input above.

cURL

curl -X POST "https://api.apify.com/v2/acts/actor-forge~website-screenshot/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"urls": ["https://apify.com", "https://en.wikipedia.org/wiki/Web_scraping"]}'

JavaScript (Node.js)

// Node.js 18+ (built-in fetch). Set APIFY_TOKEN in your environment.
const input = {
  "urls": [
    "https://apify.com",
    "https://en.wikipedia.org/wiki/Web_scraping"
  ]
};

const res = await fetch(
  "https://api.apify.com/v2/acts/actor-forge~website-screenshot/run-sync-get-dataset-items",
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.APIFY_TOKEN}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(input),
  }
);
const items = await res.json();
console.log(items.length, items[0]);

Python

# pip install apify-client   (set APIFY_TOKEN in your environment)
import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run_input = {
    "urls": [
        "https://apify.com",
        "https://en.wikipedia.org/wiki/Web_scraping"
    ]
}

run = client.actor("actor-forge/website-screenshot").call(run_input=run_input)
for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item)

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.
