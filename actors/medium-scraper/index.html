Medium Scraper: Articles by Author, Publication or Tag (RSS)

Latest Medium articles for any author, publication or tag from Medium's official RSS feeds: title, author, date, tags, image, link, and full article text and word count where the feed includes it. Keyword and date filters. No login. $1 per 1,000 articles.

Run on Apify →See pricing

What it does

A Medium scraper that uses Medium's own RSS feeds. Give it tags, authors or publications (including publications on their own domain) and get one clean row per story: title, author, publication date and last update, tags, cover image, clean link (tracking parameters removed) and a snippet. For author and publication feeds you also get the full article as plain text (and optionally HTML) with word count and reading time. Filter by keyword and date. Use it for content research and monitoring, tracking competitors' engineering blogs, newsletter and digest curation, topic trend analysis and feeding your own reader or LLM pipeline. $1 per 1,000 articles, with no compute bill on top; problems return a free status row instead of failing.

Limits and honest notes

  • Responsible use: articles are their authors' copyright. Use the data for research, monitoring, search and analysis, link back to the original story, and do not republish full articles without permission. This actor is not affiliated with, endorsed by or sponsored by A Medium Corporation.
  • It reads only Medium's public RSS feeds (robots.txt allows /feed) and never opens article pages, at most one feed every 1.5 s, with an honest user agent (ActorForge-Medium). There is no login, no cookies, no proxies and no paywall bypass: member-only stories appear with the snippet Medium puts in the feed.
  • Each feed lists about the 10 most recent stories, so this is a monitor for new posts, not a back-catalogue export; schedule it to build history. Tag feeds carry snippets only; author and publication feeds carry the full text. Clap and response counts are not in the feeds.
  • If Medium answers with a block or challenge page, the run stops, keeps the articles already delivered and adds a free status row. Respects your run budget: set a maximum total charge and the run stops cleanly at the cap. Unknown feeds return a free status row.

Use it from code

Run the actor through the Apify API with the input above.

cURL

curl -X POST "https://api.apify.com/v2/acts/actor-forge~medium-scraper/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"tags": ["artificial-intelligence"], "maxItems": 10}'

JavaScript (Node.js)

// Node.js 18+ (built-in fetch). Set APIFY_TOKEN in your environment.
const input = {
  "tags": [
    "artificial-intelligence"
  ],
  "maxItems": 10
};

const res = await fetch(
  "https://api.apify.com/v2/acts/actor-forge~medium-scraper/run-sync-get-dataset-items",
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.APIFY_TOKEN}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(input),
  }
);
const items = await res.json();
console.log(items.length, items[0]);

Python

# pip install apify-client   (set APIFY_TOKEN in your environment)
import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run_input = {
    "tags": [
        "artificial-intelligence"
    ],
    "maxItems": 10
}

run = client.actor("actor-forge/medium-scraper").call(run_input=run_input)
for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item)

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.
