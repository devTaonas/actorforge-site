What it does

When you analyse YouTube comments, the useful part is what people said, not who said it. Yet most comment exports hand you display names, channel IDs and profile pictures, which turns a sentiment dataset into a list of identifiable people you then have to manage. This actor strips those fields from every row by design.

It reads comments through the official YouTube Data API v3 with your own free API key. Each row holds the comment text, like count, reply count, published and edited dates, comment ID and video ID. Turn on includeReplies to add replies as their own rows, linked to the parent by parentId and capped by maxRepliesPerComment (default 20), so one enormous thread cannot consume the run.

It fits sentiment analysis, audience research, product feedback mining, LLM and RAG datasets and moderation reviews. Comments cost $0.50 per 1,000, and one free key covers about 1 million comments a day. If you need to know who commented, this is deliberately not the tool for that.

How it works

  1. Video URLs or IDs are read from videoUrls and comment threads are fetched with commentThreads.list, 100 per call.
  2. Top-level comments are capped per video by maxCommentsPerVideo, sorted newest first or by YouTube's top comments via commentOrder.
  3. With includeReplies on, up to 5 replies come with each thread call, and longer threads are fetched with comments.list up to maxRepliesPerComment.
  4. Author display name, channel ID, profile image and channel URL are removed from every row before it is written to your dataset.
  5. Videos with comments turned off, or that are private or deleted, produce a free error row.

Use cases

Sentiment analysis on a launch video

Export the top or newest comments on a product launch, trailer or ad and score them with your own model. Because author fields are gone, the dataset is just text, likes and timestamps.

Training and RAG datasets

Collect comment text across many videos for classification, topic modelling or retrieval experiments without storing commenter identities alongside it. Remember that @mentions typed inside a comment stay in the text.

Product feedback mining

Use searchTerms to have YouTube return only comments containing a keyword, such as a feature name or a bug, then read or cluster just those.

Moderation and community review

Pull the newest comments with commentOrder set to time on a schedule and review them in a spreadsheet, using like and reply counts to prioritise.

Limits and honest notes

  • You need your own free YouTube Data API v3 key (see the 4-step guide above). Without one the run stops at once with instructions, and nothing is charged.
  • Quota is per Google Cloud project: 10,000 units/day for free. Unit costs: videos.list, channels.list, playlistItems.list, commentThreads.list and comments.list cost 1 unit each, and search.list costs 100. A quotaExceeded error stops the run cleanly; rows already delivered are kept, and the failed call is free.
  • Only public data the API returns for an API key: no private or unlisted-by-ID-only details, no dislike counts (removed by YouTube), no revenue, no watch time, and no subscriber lists. Channels that hide their subscriber count give subscriberCount: null.
  • Like counts that the creator hides come back as null. Counts are YouTube's own; subscriber counts are rounded by YouTube to 3 significant figures.
  • Free rows (type error) cover invalid inputs, videos and channels that are not found, private or deleted, and videos with comments disabled.
  • You must refresh or delete stored API data within 30 days (YouTube Developer Policies III.E.4). We keep nothing after the run.
  • The run's spend limit is respected: each page of rows is charged before it is delivered, and the run stops cleanly at the cap.
  • Author identity is never returned: no display name, author channel ID, profile image or channel URL. If you need commenter lists, this is not the actor for you. The comment text itself is returned as written, so an @mention a commenter typed stays in the text.
  • The API does not say whether a comment is pinned or hearted by the creator, so those fields are not in the rows. Videos with comments turned off give a free error row.
  • maxCommentsPerVideo counts top-level comments only. Replies are capped per comment by maxRepliesPerComment (default 20, 0 = no replies, max 1,000). Up to 5 replies come with the thread call; more cost 1 extra quota unit per 100 replies. Every reply is its own comment-result row.

FAQ

How can I export YouTube comments to CSV for sentiment analysis?

Add the video links to videoUrls, pick how many top-level comments you want with maxCommentsPerVideo, and run. The dataset can be downloaded as CSV, JSON or Excel, with one row per comment and no author fields.

Does the export include commenter usernames?

No. Display name, author channel ID, profile image and channel URL are stripped from every row. The comment text is returned as written, so an @mention someone typed stays in the text.

Are replies counted against the comment limit?

No. maxCommentsPerVideo counts top-level comments only. Replies are capped per thread by maxRepliesPerComment (default 20, 0 for none, up to 1,000), and each reply is its own billed row.

How many YouTube comments can I download per day?

Comment threads cost 1 quota unit per 100 comments, so the 10,000 free daily units on one key cover about 1 million comments. Long reply threads use 1 extra unit per 100 replies beyond the first 5.

What happens if a video has comments turned off?

You get a free error row for that video and the run continues with the others. Nothing is charged for it.
