Brand Mentions Monitor: Hacker News, Bluesky, GitHub, Lemmy

Find public mentions of your brand, product or keyword on Hacker News, Bluesky, Lemmy, Mastodon, GitHub issues and DEV in one run: text, link, author handle, time, likes and replies. Monitor mode returns only new mentions. No API keys. $0.40 per 1,000 mentions.

What it does

Monitor public mentions of your brand, product, library or any keyword across the open developer and tech communities, in one run and one table. Give it keywords and it searches Hacker News (stories and comments), Bluesky (posts and replies), Lemmy (posts and comments on large federated instances), Mastodon (public hashtag timelines), GitHub (issues and pull requests) and DEV / dev.to (articles by tag), then returns one normalised row per mention: source, link, title and text snippet, the public author handle, time posted, likes, replies, reposts and score, where it was posted (HN thread, Lemmy community, GitHub repo, hashtag) and which keyword matched. Filter by time window (last hour to last year), exclude noise words, drop comments, pick a Bluesky language or author. Switch on monitor mode for scheduled runs and each run returns only mentions you haven't seen yet, which makes it a cheap social listening and brand monitoring feed for devrel teams, open-source maintainers, developer-tool startups, PR and competitor tracking, alerts to Slack via Make, n8n or Zapier, and data for AI agents. Every source is an official or documented public API used keylessly (an optional free GitHub token raises GitHub's limit); robots.txt and Crawl-delay are respected on community-run servers. Only public posts and public handles are returned: no follower lists, profiles or emails. $0.40 per 1,000 mentions, with no start fee and no compute bill on top. Runs that find nothing return a free status row instead of failing.

Limits and honest notes

  • Sources and terms: Hacker News via the Algolia HN Search API (documented by HN, no published rate limit; paced at 2 requests/s). Bluesky via the public AppView API api.bsky.app, whose robots.txt says "Crawling the public parts of the API is allowed" (one request at a time). Lemmy and Mastodon instances via their public APIs, with each server's robots.txt and Crawl-delay respected (lemmy.world asks for one request per minute). GitHub via the REST search API under the GitHub Terms (no selling of personal data, no spam; emails are never collected). DEV via the documented Forem API. Not affiliated with any of these platforms.
  • Mastodon and DEV have no keyless full-text search, so there the keyword is matched as a hashtag or tag ("Next.js" → #nextjs, "open ai" → #openai). Hacker News, Bluesky, Lemmy and GitHub search the full text.
  • Reddit and X/Twitter are not included: their APIs need paid or commercial agreements.
  • Privacy: only public posts, their links and public handles are returned; no follower lists, profile details or emails. Bluesky accounts that opted out of logged-out visibility and Mastodon accounts marked noindex are skipped. Monitor mode stores only hashed IDs of delivered rows. Text is a snippet (up to 1,000 characters), not an archive copy; please respect deletions and the platforms' terms when you store or republish.
  • GitHub allows 10 keyless search requests per minute per IP (shared on Apify), so GitHub is paced at one request every 6.5 s and skipped with a note if the limit is hit; add a free personal access token (no scopes) for 30/min. With many keywords, Lemmy's Crawl-delay also makes runs slower (about a minute per extra keyword).
  • If one source is down or refuses a request, the run logs it in the summary and continues with the others; it never fails because of one source.
  • Results are newest first per source. maxResultsPerSource is shared fairly between keywords.
  • Respects your run budget: set a maximum total charge and the run stops cleanly at the cap, with nothing charged twice. A run with no matches returns one free status row explaining why.

Use it from code

Run the actor through the Apify API with the input above.

cURL

curl -X POST "https://api.apify.com/v2/acts/actor-forge~dev-community-mentions/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"keywords": ["openai"], "sources": ["hackernews", "bluesky", "lemmy", "github"], "maxResultsPerSource": 5, "sinceHours": 168}'

      "Content-Type": "application/json",

  }
);
const items = await res.json();
console.log(items.length, items[0]);

Python

# pip install apify-client   (set APIFY_TOKEN in your environment)
import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run_input = {
    "keywords": [
        "openai"
    ],
    "sources": [
        "hackernews",
        "bluesky",
        "lemmy",
        "github"
    ],
    "maxResultsPerSource": 5,
    "sinceHours": 168
}

run = client.actor("actor-forge/dev-community-mentions").call(run_input=run_input)
for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item)

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.
