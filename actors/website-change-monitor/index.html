Website Change Monitor — Page Diff, CSS Selector & Webhook

Monitor web pages for changes on a schedule: compares each page with the previous run (readable text, HTML or CSS-selector elements), ignores timestamps and noise, returns a unified diff and posts changes to Slack, Discord, Zapier, Make or n8n. A Visualping alternative at $2 per 1,000 checks.

Run on Apify →See pricing

What it does

Get told when a web page changes, without checking it yourself. This website change monitor fetches each of your URLs, compares it with what it saw on the previous run, and returns one row per page: baseline (first check), unchanged, changed (with a unified diff, added/removed line counts and percent changed) or error. Use it for page change detection on competitor pricing pages, product and stock pages, terms of service and privacy policies, job boards, government notices, documentation and changelogs. It is a Visualping alternative (and ChangeTower / Distill alternative) that you own: results land in an Apify dataset and API, and changes can be posted to Slack, Discord, Zapier, Make, n8n or your own webhook.

Three ways to compare. text (default) compares the readable page as Markdown, without menus, header, footer, cookie banners or scripts, so redesigns and ad rotations don't trigger alerts. html compares the markup itself (scripts and styles excluded) to catch changed links, images and attributes. selector watches only the elements you name with CSS selectors, e.g. .price or #pricing-table: the cheapest way to monitor competitor prices or one section of a busy page.

Limits and honest notes

  • You pay only for pages that were fetched and compared. Errors are free: timeouts, HTTP 4xx/5xx, robots.txt blocks, unsupported file types (images, PDFs, binaries), a selector that matches nothing, blocked internal addresses. Error rows never overwrite the saved snapshot.
  • The first run of a monitor (or the first time a URL is seen) is a baseline: only page-checked is charged and there is nothing to diff yet. Changing the mode, selectors or ignore rules also starts a new baseline instead of reporting a false change.
  • Pages are fetched with plain HTTP (no browser), which keeps checks cheap and fast. Content that only appears after JavaScript runs is not seen; such pages are reported as an error (no text content) or compare only their static HTML. Sites with CAPTCHAs or strong bot protection are out of scope.
  • Up to 5,000 URLs per run (maxUrls, default 500), 10 in parallel by default (up to 50), at most 2 at a time per site. Pages larger than 10 MB are skipped; compared content is capped at 1 million characters and the diff at about 20 KB per page (counts stay exact).
  • Snapshots are kept per monitor name in your own Apify account (named key-value store af-page-monitor-<name>), so separate schedules need separate monitor names. Deleting that store resets the monitor to baselines.
  • robots.txt is respected by default. If a site's robots.txt can't be fetched (HTTP 5xx or a network error, after one retry), that site's URLs get a free error row for the run (RFC 9309) and their saved snapshots are kept. Requests to localhost, private networks and cloud-metadata addresses are blocked for pages and webhooks, including after redirects; webhooks do not follow redirects.
  • Proxy: off by default; Apify datacenter proxy and your own proxy URLs are supported, residential and SERP groups are not.
  • Respects your run budget: set a maximum total charge and the run stops cleanly at the cap. Pages not checked keep their snapshot, so the next run still reports their changes.

Use it from code

Run the actor through the Apify API with the input above.

cURL

curl -X POST "https://api.apify.com/v2/acts/actor-forge~website-change-monitor/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"urls": ["https://www.iana.org/help/example-domains", "https://news.ycombinator.com/"], "cssSelector": [], "ignoreSelectors": [], "ignorePatterns": [], "proxyConfiguration": {"useApifyProxy": false}}'

const items = await res.json();

Python

# pip install apify-client   (set APIFY_TOKEN in your environment)
import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run_input = {
    "urls": [
        "https://www.iana.org/help/example-domains",
        "https://news.ycombinator.com/"
    ],
    "cssSelector": [],
    "ignoreSelectors": [],
    "ignorePatterns": [],
    "proxyConfiguration": {
        "useApifyProxy": False
    }
}

run = client.actor("actor-forge/website-change-monitor").call(run_input=run_input)
for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item)

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.
