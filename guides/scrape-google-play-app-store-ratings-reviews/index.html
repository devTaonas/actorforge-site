How to Scrape Google Play and App Store Ratings, Reviews and Charts

Uses App Store & Google Play Scraper — Apps, Charts, Reviews

Short answer: List apps by Google Play package name or App Store id (or paste their store URLs), choose countries, and App Store & Google Play Scraper returns one normalised row per app, store and country with rating, ratings count, histogram, installs, price and version. Switch on reviews for up to 20 anonymised Google Play reviews per app, or add Apple's top charts to discover apps.

App store data drives a lot of everyday decisions: which competitor shipped an update, whose rating dropped after a release, how a category's top charts move from week to week, and what users complain about in reviews. Both stores show this publicly on their app pages, but in two different shapes, in many countries, with no export button.

App Store & Google Play Scraper reads those public pages (and Apple's official marketing RSS feed for charts) and maps both stores into one schema, so a Google Play row and an App Store row for the same app sit side by side in one table.

This guide shows how to find the right identifiers, build a multi-country competitor table, pull reviews for sentiment work, and schedule a monitor. It is also upfront about what the public pages do not offer, because that matters for planning: there are no App Store review texts and no deep Google Play review history.

Step by step

  1. Collect the app identifiers

    For Google Play, the package name is the id parameter in the store URL: play.google.com/store/apps/details?id=com.spotify.music gives com.spotify.music. For the App Store, the number after id in the URL is the app id: apps.apple.com/us/app/spotify-music-and-podcasts/id324684580 gives 324684580. You can paste either form into apps; the actor works out which store each line belongs to. Keyword search is not available (both stores disallow their search pages in robots.txt), so start from a list you know, or from the charts in step 4.

  2. Pick countries and language

    countries takes two-letter store codes (us, gb, de, jp, br and so on, up to 50). Each app is fetched once per country, because ratings, prices and even availability differ by storefront. language sets the language of Google Play text and reviews (en, de, pt-BR); App Store text always comes in the storefront's own language.

  3. Build a competitor table

    Put your app and its competitors in apps and run. You get rows of type: app with title, developer, rating, ratings count, the 1 to 5 star histogram, installs (Google Play only), price, in-app purchases, content rating, version, release and update dates, plus similar apps and more apps by the same developer. Rating histograms are often more telling than the average: a rising share of 1-star ratings after an update shows up there first.

    {
  "apps": [
    "com.spotify.music",
    "com.soundcloud.android",
    "https://apps.apple.com/us/app/spotify-music-and-podcasts/id324684580"
  ],
  "countries": ["us", "gb", "de"],
  "language": "en"
}

  4. Discover apps from Apple's top charts

    Add top-free and/or top-paid to charts and set chartSize (1 to 100). Each chart position becomes a type: chart row for every country you chose. Turn on includeChartAppDetails to also fetch a full app row for each charting app, which is a cheap way to snapshot a market. Google Play charts are not supported.

  5. Pull Google Play reviews for sentiment work

    Turn on includeReviews. For each app, country and language you get up to 20 reviews, the "most relevant" set the public page shows, as type: review rows with rating, text, date, thumbs-up count, app version and the developer's reply. Reviewer names, avatars and user ids are removed. Use reviewsSince to drop older ones. Twenty reviews per app is a sample, not a census, so treat it as a qualitative signal.

    import os
import pandas as pd
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run = client.actor("actor-forge/app-store-scraper").call(run_input={
    "apps": ["com.spotify.music", "com.soundcloud.android"],
    "countries": ["us", "gb"],
    "includeReviews": True,
})
rows = pd.DataFrame(client.dataset(run["defaultDatasetId"]).list_items().items)

reviews = rows[rows["type"] == "review"]
print(reviews.groupby("appVersion")["rating"].agg(["count", "mean"]).tail(10))

  6. Schedule it as a monitor

    Save the input as a task and add a daily or weekly schedule in Apify. Turn on onlyNewReviewsSinceLastRun and each run returns only reviews it has not delivered before (state is kept in a key-value store in your account), so you pay once per review and build up history over time. Compare version and updatedAt between runs to detect releases.

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.

What it costs

App rows are $0.0008 each (one app in one country), chart positions $0.0002, and Google Play reviews $0.00004. Tracking 30 apps in 5 countries is 150 app rows, $0.12 per run. Adding 20 reviews for each of those 150 app-country pairs adds 3,000 reviews, $0.12. A top-25 free and top-25 paid chart for one country costs $0.01. Error rows (app not found in a country, store blocked) are free.

Tips and pitfalls

  • Run the same apps in several countries if you sell internationally. Ratings and review themes can differ a lot between storefronts.
  • An app missing from one country gives a free error row, not a failed run, so you can safely use one country list for all apps.
  • Google Play no longer shows app size on the web, so size is null for Play apps. App Store rows have size but no installs.
  • Developer e-mails are kept only when they are company support mailboxes on the developer's own domain.

Limitations

  • No keyword search in either store, because both stores' robots.txt disallow their search pages. Start from ids, URLs or Apple's charts.
  • No App Store review texts. Apple's review feed sits under a path its robots.txt disallows, so App Store rows have rating, count and histogram only.
  • Google Play reviews are capped at the 20 "most relevant" reviews per app, country and language, with no newest-first sort and no deep history. Monitoring mode builds history going forward.
  • If a store shows a CAPTCHA or keeps answering 429/403, the actor stops asking that store for the rest of the run and returns free error rows. It uses no proxies and does not solve CAPTCHAs.

Responsible use

Review text is returned as the user wrote it, but without names or ids. Keep it that way: do not try to re-identify reviewers, and quote reviews in aggregate rather than as a list of individuals' opinions.

The actor re-checks each store's robots.txt at the start of every run and reads only allowed pages, at most two requests at a time per store with pauses. Store data is the stores' and developers' content, so check the store terms before republishing it.

FAQ

Can I get App Store reviews?

No. Apple's customer-review feed is under a path that Apple's robots.txt disallows, so this actor does not read it. App Store rows still include the rating, ratings count and star histogram.

Why do I only get 20 Google Play reviews per app?

That is what the public app page shows. Google's paging endpoints for reviews are disallowed by its robots.txt. Run the actor on a schedule with onlyNewReviewsSinceLastRun to accumulate more over time.

Can I search for apps by keyword?

No, both stores disallow their search pages in robots.txt. Use package names, App Store ids or URLs, or start from Apple's top free and top paid charts.

Does it return the same fields for both stores?

Yes, both stores are mapped to one schema. Fields a store does not publish (installs on the App Store, size on Google Play) are null.
