How to Monitor Brand Mentions on Hacker News, Bluesky, GitHub and Mastodon

Uses Brand Mentions Monitor: Hacker News, Bluesky, GitHub, Lemmy

Short answer: Enter your brand, product or library names in Brand Mentions Monitor, pick sources and a time window, and get one normalised row per public mention across Hacker News, Bluesky, Lemmy, Mastodon, GitHub issues and pull requests, and DEV. Schedule it with newSinceLastRun on to receive only mentions you have not seen.

For a developer tool, an open-source project or a tech startup, the conversations that matter rarely happen where general social-listening tools look. A Hacker News thread, a GitHub issue in someone else's repository, a Bluesky post from a well-known engineer or a Lemmy discussion can move sign-ups or reveal a bug days before a support ticket arrives.

Each of those platforms has a public API, and each has its own query syntax, pagination, rate limits and data shape. Brand Mentions Monitor queries all six with your keywords, keyless (an optional free GitHub token raises GitHub's limit), and returns the results in one schema: source, link, title and text snippet, public author handle, time, likes, replies, reposts and score.

This guide covers choosing keywords that avoid noise, picking sources, setting up a scheduled feed with only new mentions, and routing them to Slack. Reddit and X are not included, because their APIs now need paid or commercial agreements.

Step by step

  1. Choose keywords and exclusions

    Put brand names, product names and package names in keywords, for example "supabase" or "Next.js". Hacker News, Bluesky, Lemmy and GitHub search the full text. Mastodon and DEV have no keyless full-text search, so there the keyword is used as a hashtag or tag ("Next.js" becomes #nextjs). If your name is a common word, add excludeKeywords for the unrelated meanings, and words such as "hiring" if job posts are noise for you.

  2. Pick sources and a time window

    sources defaults to all six: hackernews, bluesky, lemmy, mastodon, github and devto. Drop the ones that are irrelevant to you; GitHub is the most useful for libraries, Hacker News and Bluesky for launches and opinions. sinceHours sets how far back to look (168, one week, by default; up to 8,760). maxResultsPerSource caps rows per source, shared fairly between keywords, newest first.

  3. Tune per-source options

    includeComments (on by default) adds Hacker News and Lemmy comments and Bluesky and Mastodon replies; turn it off for top-level posts only. blueskySort can be latest or top, blueskyLanguage limits posts to one language and blueskyAuthor tracks a single account (for example your own). Add a free GitHub personal access token with no scopes in githubToken to go from 10 to 30 search requests per minute.

    {
  "keywords": ["supabase", "supabase-js"],
  "excludeKeywords": ["hiring"],
  "sources": ["hackernews", "bluesky", "github", "lemmy"],
  "sinceHours": 24,
  "maxResultsPerSource": 100,
  "includeComments": true,
  "newSinceLastRun": true
}

  4. Schedule it and receive only new mentions

    Save the input as a task with newSinceLastRun on and schedule it, for example every six hours. Each run skips mentions already delivered for the same keywords and sources, so you see and pay for each mention once. Only hashed ids are stored, in a key-value store named dev-community-mentions-state in your account. A run with nothing new returns one free status row.

  5. Route mentions to Slack and triage them

    Connect the task to Slack through Make, n8n, Zapier or an Apify webhook, and post source, title or the start of text, likeCount and url. Sort by engagement so a Hacker News story with a high score or a Bluesky post with many reposts reaches someone quickly. For a weekly report, aggregate mentions per source and day.

    import os
import pandas as pd
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run = client.actor("actor-forge/dev-community-mentions").call(run_input={
    "keywords": ["supabase"],
    "sinceHours": 168,
    "maxResultsPerSource": 100,
})
df = pd.DataFrame(client.dataset(run["defaultDatasetId"]).list_items().items)
df = df[df["type"] == "mention"]

df["engagement"] = df[["likeCount", "replyCount", "repostCount", "score"]].fillna(0).sum(axis=1)
print(df.sort_values("engagement", ascending=False)[["source", "engagement", "url"]].head(10))
print(df.groupby(["source", pd.to_datetime(df["createdAt"]).dt.date]).size().unstack(0).fillna(0))

  6. Add news coverage alongside

    Community mentions and press coverage are different audiences. Run News Search with the same keywords to see articles from news sites worldwide over the last 72 hours, and keep both feeds in one channel or sheet.

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.

Tips and pitfalls

  • Lemmy's largest server, lemmy.world, asks for one request per minute in its robots.txt, and the actor respects it, so every extra keyword adds about a minute. Fewer, better keywords keep runs fast.
  • GitHub is searched keyless at 10 requests per minute per IP, which is shared on Apify. If GitHub is skipped with a note, add a free token.
  • Package names make precise keywords (for example "supabase-js"), because they rarely appear outside technical discussion.
  • Run once with a long sinceHours to build a baseline, then switch to a short window with newSinceLastRun for the ongoing feed.

Limitations

  • Reddit and X/Twitter are not covered, because their APIs require paid or commercial agreements.
  • Mastodon and DEV are matched by hashtag or tag, not full text, so posts that mention your name without the tag are missed there.
  • Results are newest first per source, up to maxResultsPerSource; very busy keywords can exceed that in the window.
  • If one source is down or refuses a request, the run continues with the others and notes the problem in the summary.

Responsible use

Only public posts and public handles are returned. Bluesky accounts that opted out of logged-out visibility and Mastodon accounts marked noindex are skipped. Use the feed to follow conversations about your product, not to build profiles of individual people.

Text is a snippet, not an archive copy. If you store mentions, respect deletions and each platform's terms, and do not use GitHub data for spam or resale, which GitHub's terms forbid.

FAQ

Do I need API keys for these platforms?

No. All sources are queried through public, documented APIs without keys. A free GitHub token is optional and only raises GitHub's rate limit.

Why is Reddit not included?

Reddit's API now requires a commercial agreement for this kind of use, and scraping it would break its terms. The same applies to X/Twitter.

How do I avoid paying for the same mention twice?

Turn on newSinceLastRun for scheduled runs. The actor remembers hashed ids of delivered mentions for the same keywords and sources and skips them next time.

Can I track my own company account's posts?

On Bluesky, yes: set blueskyAuthor to your handle. For the other platforms, search for your brand name and filter on authorHandle in the results.
