How to Monitor News Mentions by Keyword Worldwide (Google News Alternative)

Uses News Search - Global News by Keyword, Google News Alternative

Short answer: Give News Search your keywords and filters (source domains, countries mentioned, languages, sentiment), choose how many hours back to search (1 to 72), and get one row per matching article with URL, title, source, time, tone, themes, locations and organisations. Schedule it with monitor mode on and each run returns only new articles.

Most news monitoring starts with Google News or Google Alerts. Both are fine for reading, but neither gives you structured data: Google News has no official API, scraping it is fragile and against Google's terms, and Alerts arrive as emails. Commercial media-monitoring services fix that at a monthly price that only makes sense for large PR teams.

The GDELT Project offers a third route. Every 15 minutes it publishes an open file describing the news articles it has seen worldwide: tens of thousands of sites, in English and around 65 translated languages, each article tagged with tone, themes, locations and organisations. GDELT licenses the data for unlimited commercial use with attribution.

News Search reads those files for you and filters them by your keywords and criteria. This guide covers writing keywords that match well (GDELT does not index full article text), filtering by source and country, setting up a scheduled monitor and sending alerts.

Step by step

  1. Write keywords that match GDELT's fields

    Keywords are matched as whole words, case-insensitively, in the article title, its URL, the organisations GDELT extracted and the names mentioned, not in the full body text. So include the forms that appear in headlines: the company name and its common short form ("Volkswagen", "VW"), a product name, or both "artificial intelligence" and "AI". keywordMatch set to all requires every keyword; excludeKeywords removes noise such as a homonym.

  2. Set the time window and volume

    lookbackHours goes from 1 to 72 for English-language news, measured from the newest GDELT batch; the translated feed is searched over at most 24 hours. Results come newest first. maxArticles stops the run after that many rows, which also caps the cost.

  3. Filter by source, country, language and tone

    sourceDomains limits results to sites you trust (subdomains included), and excludeSourceDomains drops press-release mills or aggregators. countries keeps articles that mention a place in a country, by English name ("Germany", "United Kingdom"). languages takes ISO codes; a non-English language switches to the translated feed automatically, or set feed to all. sentiment keeps positive (tone ≥ 1.5), negative (≤ −1.5) or neutral articles, which is handy for a "negative coverage" alert.

    {
  "keywords": ["Tesla", "Cybertruck"],
  "excludeKeywords": ["Nikola Tesla"],
  "lookbackHours": 72,
  "maxArticles": 300,
  "feed": "all",
  "countries": ["Germany", "United States"],
  "sentiment": "negative"
}

  4. Turn it into a scheduled monitor

    Save the input as an Apify task, switch on newSinceLastRun and schedule it every hour or every few hours. Each run skips the GDELT batches an earlier run with the same filters already scanned, so you only receive and pay for new articles. The state lives in a key-value store named news-search-state in your account. A run with no new matches returns one free status row instead of failing.

  5. Send new articles to Slack or a sheet

    Attach an Apify integration or webhook to the task, or call the API from Make, n8n or Zapier when a run succeeds, and post title, sourceDomain and url to a channel. For analysis, pull the rows into pandas and chart article counts and average tone per day.

    import os
import pandas as pd
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run = client.actor("actor-forge/news-search").call(run_input={
    "keywords": ["Nvidia"],
    "lookbackHours": 72,
    "maxArticles": 1000,
})
df = pd.DataFrame(client.dataset(run["defaultDatasetId"]).list_items().items)
df = df[df["type"] == "article"]

df["hour"] = pd.to_datetime(df["publishedAt"]).dt.floor("6h")
print(df.groupby("hour").agg(articles=("url", "count"), tone=("tone", "mean")))
print(df["sourceDomain"].value_counts().head(15))

  6. Fetch full text only for the articles you need

    Rows carry the title and metadata, not the article body. When you need the text, for summaries or an LLM digest, pass the selected URLs to Any URL to Markdown. Doing it for a filtered shortlist rather than every row keeps costs down and limits how much publisher content you copy.

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.

Tips and pitfalls

  • Run a broad search with no sourceDomains once, look at sourceDomain counts, then build your include and exclude lists from what you see.
  • GDELT sometimes skips or delays a 15-minute batch. Missing batches are listed in the run summary, so check it if a known article is missing.
  • themes takes GDELT GKG theme codes or prefixes (ECON_STOCKMARKET, ECON, TAX_FNCACT). Theme filters work well for topic monitoring when there is no single keyword.
  • For mentions in developer and tech communities rather than news, use the Brand Mentions Monitor with the same keywords.

Limitations

  • Only the last 72 hours (24 hours for the translated feed). This is a monitoring tool, not a news archive.
  • Keywords are not matched against the article body, so recall is lower than a full-text search engine.
  • No article bodies, no "top stories" ranking, and no paywalled, print or broadcast coverage beyond what GDELT's web monitoring sees.
  • publishedAt is when GDELT saw the article, not the publisher's own timestamp.

Responsible use

Keep the GDELT credit from the source field when you republish rows; it is the condition of GDELT's open licence. Headlines and article text belong to their publishers, so link to articles rather than copying them in full.

includePeople is off by default. If you switch it on, the names are mostly public figures; do not use the feed to track private individuals.

FAQ

Does it need an API key?

No. GDELT's files are public, and the actor reads them directly.

Can I search news older than three days?

No. The actor scans the GDELT batches of the last 72 hours. For history, schedule it now with monitor mode and store the results as they come in.

Does it cover non-English news?

Yes, through GDELT's translated feed, which covers about 65 languages over the last 24 hours. Titles stay in the original language; themes and organisations are in English.

Is it affiliated with Google News?

No. It does not touch Google at all. It is an alternative built on the GDELT Project's open data and is not affiliated with GDELT either.
