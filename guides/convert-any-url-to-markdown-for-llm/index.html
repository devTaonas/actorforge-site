How to Convert Any URL to Markdown for LLMs and RAG

Uses Any URL to Markdown — Web Pages, PDF, Word, Excel & OCR

Short answer: Pass one URL or a list to Any URL to Markdown. It detects whether each link is a web page, a PDF, an Office file, an e-book, CSV, JSON or an image, picks the matching converter and returns one row per URL with clean Markdown, a title, metadata and a token estimate.

LLMs read Markdown well. Headings, lists and tables survive, and the noise of raw HTML (navigation, scripts, cookie banners, inline styles) is gone, so the same content costs far fewer tokens. The trouble is that the links you want to feed a model are rarely all web pages. A research agent finds a PDF report, a pricing spreadsheet, a slide deck and a blog post, and each needs a different parser.

Any URL to Markdown puts those parsers behind one input. Web pages go through Mozilla Readability, PDFs are read from their text layer with heading detection, DOCX, XLSX, PPTX, OpenDocument and EPUB files are converted with their tables kept, and images or scanned PDF pages go through Tesseract OCR. Every row says which route was used, so you can check the result.

This guide covers a single conversion, batch conversion for a RAG index, calling it from an agent, and keeping the cost predictable. If your sources are mostly PDFs, the PDF to Markdown guide goes deeper on that format.

Step by step

  1. Try one URL first

    Open the actor on Apify and put a link in url. The prefilled example is the arXiv PDF of "Attention Is All You Need". Run it and look at the row: detectedFormat says what the file really was (a link ending in .php can still be a PDF), route says which converter ran, and tokenEstimate gives a rough size for your context window. Check markdown for the structure you expect: headings as #, tables as pipe tables.

  2. Decide how much of each web page to keep

    onlyMainContent is on by default and keeps only the article or main block, which is what you want for blog posts, documentation and news. Turn it off for pages where the useful content sits outside the main block, such as a pricing page with several comparison tables. Turn on includeText if you also need a plain-text version, for example to compute embeddings on text without Markdown syntax.

  3. Set limits for documents and OCR

    PDFs are read up to maxPdfPages (500 by default). Pages without a text layer are sent to OCR only while ocr is on and only up to maxOcrPages per PDF (20 by default), because OCR is the expensive route. If you never want to pay for OCR, switch ocr off: images and scanned pages then come back as free error rows. For spreadsheets, maxRowsPerSheet cuts each sheet at 1,000 rows by default, and cut rows are flagged truncated: true.

    {
  "url": "https://en.wikipedia.org/wiki/Retrieval-augmented_generation",
  "urls": [
    "https://arxiv.org/pdf/1706.03762",
    "https://calibre-ebook.com/downloads/demos/demo.docx"
  ],
  "onlyMainContent": true,
  "includeText": false,
  "ocr": true,
  "ocrLanguages": ["eng"],
  "maxOcrPages": 10,
  "maxPdfPages": 300
}

  4. Batch convert a list of sources for your index

    Put up to 1,000 links in urls (duplicates are removed). Each row is independent, so one bad link does not fail the run: failed downloads, robots.txt blocks, unsupported formats and empty pages come back as error rows and are not charged. After the run, filter on the rows that have Markdown and send them to your chunker.

    import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
sources = open("sources.txt").read().split()

run = client.actor("actor-forge/any-url-to-markdown").call(run_input={
    "urls": sources,
    "onlyMainContent": True,
    "maxOcrPages": 10,
})

docs = []
for row in client.dataset(run["defaultDatasetId"]).iterate_items():
    if not row.get("markdown"):
        print("no Markdown for", row.get("url"))
        continue
    docs.append({"source": row["url"], "title": row.get("title"), "text": row["markdown"]})

print(len(docs), "documents,", sum(len(d["text"]) // 4 for d in docs), "tokens (approx.)")

  5. Chunk by heading before embedding

    Because headings are kept, you can split on them instead of on a fixed character count, which keeps each chunk about one topic. A simple approach is to split on lines starting with # or ##, then split any chunk that is still too long. Store url and title with every chunk so answers can cite their source.

  6. Call it from an agent or a workflow

    The input is one string and the output is one Markdown string, which suits tool calls. In an MCP client, n8n, Make or Zapier, call the actor's run-sync endpoint with {"url": "..."} and read markdown from the first row. Use tokenEstimate to decide whether the page fits in the remaining context or needs summarising first.

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.

Tips and pitfalls

  • Point the actor at the document itself, not a viewer page. A Google Drive or SharePoint preview URL is a web page that wraps the file and usually needs a login.
  • For OCR, set ocrLanguages to the languages actually in the documents (up to 3). Wrong languages produce noticeably worse text. For more than the 7 built-in languages, use OCR to Text.
  • Keep the route column in your index. If answers built on image-ocr rows look wrong, you know where to look.
  • Large spreadsheets are better handled as data than as Markdown. Raise maxRowsPerSheet only if the model really needs the rows.

Limitations

  • Pages are fetched as static HTML without a browser. Single-page apps that render content with JavaScript come back as a free error row, not as Markdown.
  • It converts the URLs you give it and does not crawl or follow links.
  • Legacy .doc, .xls and .ppt files, RTF, .odp, HEIC/AVIF and SVG are not supported (reported, not charged). Files over 50 MB, password-protected PDFs and pages behind a login cannot be read.
  • OCR covers English, German, French, Spanish, Italian, Portuguese and Dutch. Handwriting and blurry photos convert poorly.

Responsible use

The actor respects robots.txt by default (including on redirects and direct file links), identifies itself with an honest user agent and backs off when a site answers 429 or 403. Leave respectRobotsTxt on.

Converting a page does not give you rights to its content. Check the licence or terms before you store third-party documents in an index that other people can query, and keep the source URL with every chunk.

FAQ

Does it handle pages that need JavaScript?

No. It reads the HTML the server sends. Pages that are an empty app shell without JavaScript are reported as an error and not charged; use a browser-based crawler for those.

How accurate is tokenEstimate?

It is the character count divided by 4. For English text with GPT and Claude tokenizers that is usually close enough to plan context use, but it is not an exact count, and it is less accurate for code and non-Latin scripts.

Can I convert a whole website?

Not with this actor; it converts only the URLs you list. Build the list first, for example from the site's sitemap, then pass it in urls (up to 1,000 per run).

What happens to a link that fails?

You get a row with the reason (blocked by robots.txt, download failed, unsupported format, empty page) and it is not charged. The rest of the run continues.
