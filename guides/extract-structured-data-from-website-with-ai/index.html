How to Extract Structured Data From Any Website With AI (No Selectors)

Uses AI Web Extractor - Structured Data from Any Website with AI

Short answer: Give AI Web Extractor a list of URLs and a plain-English instruction, optionally with a field list or JSON schema. Each page is fetched, cleaned to compact Markdown and sent to a low-cost LLM in JSON mode; you get one JSON object per page, or one row per item in list mode. Token spend is capped by maxLlmCostUsd.

Classic scrapers break when a site changes its layout, because they depend on CSS selectors or XPath tied to the page structure. For a handful of pages on many different sites (supplier product pages, event listings, company "about" pages, job boards) writing and maintaining a selector set per site is not worth it.

An LLM can read the page the way a person does and fill in the fields you ask for. AI Web Extractor handles the plumbing around that: it fetches each page, strips navigation, scripts and cookie banners, converts it to compact Markdown, trims it to a token budget, calls the model in JSON mode, then validates the reply and repairs it if it was cut off. The default model is Google Gemini 2.5 Flash Lite through Apify's OpenRouter integration; any OpenRouter model id works.

This guide covers writing an instruction that extracts reliably, using a schema, list mode for catalogues, crawling one site, and keeping the two parts of the bill under control. Be clear on the trade-off: AI extraction is flexible but not deterministic, so check what matters.

Step by step

  1. Start with one page and a precise instruction

    Put one URL in startUrls and describe exactly what you want in instruction, including formats: "Extract the product name, the price as a number without currency sign, the currency code and whether it is in stock (true/false)." The model is told to use only what is on the page and return null for anything missing. Turn on includeMarkdown for the first runs so you can see the text the model actually received.

  2. Pin the shape with a schema

    For stable columns, add schema. The simple form is a map of field names to descriptions. A full JSON Schema also works and is passed to the model as a structured-output schema, which makes types more reliable. Field names in the schema become the keys of data in every row.

    {
  "startUrls": [{ "url": "https://books.toscrape.com/" }],
  "instruction": "List every book on the page with its title, price and star rating.",
  "outputMode": "list",
  "schema": {
    "title": "book title",
    "price": "number, no currency sign",
    "currency": "ISO currency code",
    "rating": "integer 1-5"
  },
  "maxPages": 5,
  "maxLlmCostUsd": 0.05
}

  3. Use list mode for listings and catalogues

    Set outputMode to list when one page holds many items: a product grid, search results, a job board, a directory. The schema then describes one item, and each item becomes its own row with itemIndex. A list page is still charged once by the actor, however many rows it yields. A list of 50 items needs roughly 1,500 to 3,000 output tokens, so raise maxOutputTokens if rows say truncated: true.

  4. Crawl one site, narrowly

    To follow links from the start pages, set maxCrawlDepth to 1 or 2. The crawl stays on the same host. Use includeGlobs such as https://example.com/products/** and excludeGlobs such as **/cart** to keep it on the pages you want, and maxPages to stop after a number of successfully extracted pages.

  5. Set both cost limits

    There are two lines on the bill. The actor's own fee is $0.003 per extracted page and is limited by the run's maximum total charge. The AI tokens are charged separately to your Apify account by Apify's OpenRouter actor at OpenRouter's rates, ten times that on Apify's free plan, and are limited by maxLlmCostUsd (default $0.10): before each page the worst-case token cost is reserved, and the run stops cleanly before passing the cap. Lower maxInputTokens (default 8,000) to make long pages cheaper; turn off includeLinks if you do not need URLs back.

  6. Validate the results

    Every row has inputTokens, outputTokens and llmCostUsd, so you can see what each page cost. Spot-check a sample against the pages, and add rules in your own code for fields that matter (price is a positive number, URL is absolute). If a model keeps getting a field wrong, make the instruction more specific or try a stronger model such as google/gemini-2.5-flash on that site only.

    import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run = client.actor("actor-forge/ai-web-extractor").call(run_input={
    "startUrls": [{"url": "https://books.toscrape.com/"}],
    "instruction": "List every book with title and price as a number.",
    "outputMode": "list",
    "schema": {"title": "book title", "price": "number"},
    "maxLlmCostUsd": 0.05,
})
rows = list(client.dataset(run["defaultDatasetId"]).iterate_items())
items = [r["data"] for r in rows if r.get("data")]
bad = [i for i in items if not isinstance(i.get("price"), (int, float)) or i["price"] <= 0]
print(len(items), "items,", len(bad), "need review")
print("token cost $", round(sum(r.get("llmCostUsd") or 0 for r in rows), 5))

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.

Tips and pitfalls

  • Ask for units and formats explicitly ("number, no currency sign", "ISO date"). Vague instructions produce strings like "£51.77" in one row and 51.77 in the next.
  • Turn on onlyMainContent for articles and blog posts; leave it off for product pages and listings, where the data is often outside the main article block.
  • For product pages with structured data in the HTML, AI extraction is still convenient, but a deterministic parser will be cheaper at large volumes.
  • Pages that are empty without JavaScript return a free needs-javascript status row. If you only need clean text for your own pipeline, Any URL to Markdown skips the model entirely.

Limitations

  • Pages are fetched as static HTML with no browser. JavaScript-only sites, logins, CAPTCHAs and bot walls are not supported, and the actor does not try to get around them.
  • LLMs can be wrong or miss items, especially on long pages cut by maxInputTokens. Check important data.
  • Token charges are separate from the actor's price and are not limited by the run's maximum total charge; use maxLlmCostUsd. Your Apify billing page is the authoritative figure.
  • Crawling is same-host only, up to depth 2.

Responsible use

robots.txt is respected by default and requests identify themselves as ActorForge-AIWebExtractor. Page text is treated as data and the model is told to ignore instructions inside pages, but no prompt-injection defence is perfect, so do not pipe extracted text straight into actions without checks.

By default the model is told not to return private individuals' contact details, and personal-looking emails are replaced (role mailboxes such as info@ are kept). Switch allowPersonalData on only if you have a lawful basis to process personal data.

FAQ

Do I need an OpenAI or OpenRouter API key?

No. The actor calls Apify's own OpenRouter actor with your run's token, and the tokens are billed to your Apify account at OpenRouter's rates.

Which model should I use?

Start with the default google/gemini-2.5-flash-lite, which is cheap and good at extraction. Move a difficult site to a stronger model such as google/gemini-2.5-flash or openai/gpt-4o-mini if accuracy is not good enough.

What happens if my Apify account runs out of credit for tokens?

The run stops with one free status row explaining that the AI service was unavailable, and the run still finishes as succeeded.

Is this cheaper than a browser-based AI scraper?

Usually, because there is no browser to run and pages are trimmed before they reach the model. The trade-off is that it cannot read pages that need JavaScript.
