How to Get Local Business Leads Without Scraping Google Maps

Uses Business Places Data — Google Maps Alternative, 80M+ POIs

Short answer: Query the open Overture Maps places dataset by city and category with Business Places Data to get names, addresses, phones, websites and emails for every matching business, then add Facebook Page links with Facebook Pages by City. Nothing is scraped, so there are no blocks or result caps.

Google Maps is the default place people go for local leads, and scraping it is the default way people try to get them out. That route comes with proxies, CAPTCHAs, broken selectors and search results that stop at around 120 places, which is why a 'scrape every plumber in Leeds' job often turns into many overlapping searches stitched together.

There is another source for the same core fields. The Overture Maps Foundation publishes an open places dataset of 80M+ businesses worldwide, refreshed monthly and built from Meta, Microsoft, Foursquare, AllThePlaces, BrightQuery and others, under permissive licences that allow storage and resale with attribution. What it does not have is Google's review layer: no star ratings, review counts, opening hours or photos.

This guide walks through building a usable lead list from that data: finding the right category, defining the area, filtering to contactable businesses, running several cities and merging them, and adding Facebook Page links where you need a social touchpoint.

Step by step

  1. Decide which lead fields you really need

    List the columns your outreach depends on. If it is name, category, address, phone, website and a role email such as info@, open data covers it. If you qualify leads by star rating or review count, or need opening hours, this approach will not give you those and a Google Maps scraper remains the right tool for that part.

  2. Find the right category ids

    Plain words such as dentist, plumber, lawyer, coffee or hotel are mapped to Overture's taxonomy for you, and a parent category includes its children, so restaurant also returns italian_restaurant. For anything less common, run the actor once with listCategories on. It returns the category list with ids, parents and worldwide place counts, filtered by the Name contains text, and it is free.

    {
  "listCategories": true,
  "keyword": "dent"
}

  3. Define the search area

    A city name is enough for most jobs; 32,000+ cities are built in, and countryCode picks the right one when a name exists in several countries. For a tighter catchment, give lat, lon and radiusKm, and results come back nearest first with a distanceKm field. A bounding box works too, up to 1.5 x 1.5 degrees, which is about one metro area.

    {
  "lat": 53.8008,
  "lon": -1.5491,
  "radiusKm": 8,
  "categories": ["plumber"],
  "maxPlaces": 500
}

  4. Filter to businesses you can actually contact

    Turn on requireWebsite, requirePhone or requireEmail so that places without those fields are skipped; skipped places are never charged. Keep minConfidence at the default 0.5 to drop most stale or duplicate records, or raise it to 0.9 if you only want well-corroborated places. Personal-looking emails are removed automatically and counted in droppedPersonalEmails.

  5. Run several cities and merge the results

    Each run covers one area, so for a region you loop over cities. The script below runs one city at a time with the official Apify Python client, deduplicates on the place id and writes a CSV with the first phone, website and email for each business. Field values that are lists are joined so the CSV stays one row per place.

    import csv
import os

from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
cities = ["Austin, TX", "Dallas, TX", "Houston, TX", "San Antonio, TX", "Fort Worth, TX"]


def first(value):
    if isinstance(value, list):
        return value[0] if value else ""
    return value or ""


def joined(value):
    if isinstance(value, list):
        return "; ".join(str(v) for v in value)
    return value or ""


places = {}
for city in cities:
    run = client.actor("actor-forge/business-places-data").call(run_input={
        "location": city,
        "countryCode": "US",
        "categories": ["dentist"],
        "requireWebsite": True,
        "maxPlaces": 300,
    })
    for item in client.dataset(run["defaultDatasetId"]).iterate_items():
        places[item["id"]] = item

with open("dentists_texas.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.writer(f)
    writer.writerow(["name", "fullAddress", "phone", "website", "email", "confidence", "attribution"])
    for p in places.values():
        writer.writerow([
            p.get("name"), p.get("fullAddress"), first(p.get("phones")),
            first(p.get("websites")), first(p.get("emails")),
            p.get("confidence"), joined(p.get("attribution")),
        ])

print(f"{len(places)} unique places written")

  6. Add Facebook Page links where you need them

    If your outreach includes social, run the same area through Facebook Pages by City. It returns only businesses whose Overture record links a Facebook Page, with the normalised page URL and numeric page id alongside the same contact fields. Its cap is maxResults rather than maxPlaces. You can join the two datasets on website or phone.

    {
  "location": "Austin, TX",
  "categories": ["dentist"],
  "maxResults": 300,
  "minConfidence": 0.6
}

  7. Keep attribution and use the contacts lawfully

    The licences (CDLA-Permissive-2.0, Apache-2.0, CC0) let you store, enrich and resell the rows, as long as the attribution and licence texts travel with them, so keep the attribution field if you republish. Phones and emails are business contacts as published, but you are still responsible for how you contact people under GDPR, CAN-SPAM and similar laws.

The run-sync-get-dataset-items endpoint waits for the run (up to 5 minutes) and returns the dataset rows directly. For longer runs, start the run asynchronously and read the dataset when it finishes, as the Python example does. Replace APIFY_TOKEN with your own token from the Apify console.

Tips and pitfalls

  • One run covers one area of up to about one metro area. For a county or country, loop over cities rather than drawing a huge box.
  • Email coverage varies a lot by place and trade: in testing about 75% of Austin dentists had an email but only about 32% of Berlin restaurants. Use requireEmail only if email is your sole channel.
  • operatingStatus is often empty, so a closed business can still appear until a source drops it. Raise minConfidence if bounced calls are costly for you.
  • Smaller towns outside the built-in city list need a region or country in the location, for example "Dripping Springs, TX".
  • Use includeFields to keep the dataset small if you only need a few columns, but keep attribution if the data will be shown to anyone else.

FAQ

Is open places data as complete as Google Maps?

Not everywhere. Coverage is dense in North America and Europe and thinner in rural areas and parts of Africa and Asia. In the test cities almost every dentist and restaurant had a phone and a website.

Can I get more than 120 results for one search?

Yes. There is no per-search cap; one run returns up to 20,000 places for an area, ordered by confidence or by distance for a radius search.

How do I find businesses that have no website?

Leave requireWebsite off and filter the output for rows with an empty websites field. Those are often good prospects for web design or marketing services.

Do I need a proxy or a Google API key?

No. The actor reads the public Overture GeoParquet files and never calls Google, so no proxies, keys or CAPTCHAs are involved.
